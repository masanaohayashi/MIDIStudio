# MIDI Studio — 設計判断と検証事項

仕様作成時点の確定判断と、Claude Codeによる現物確認が必要な事項を区別して記録する。

## ADR-001 — MMLを正本にしない（決定済み）

- **理由**: MML StudioのMML/480PPQ/楽曲構造をそのまま流用すると、未知MIDIイベントや複雑な編集で情報が失われる。
- **決定**: 編集の正本は独自のMIDI Project + イベント集合。MMLとの連携は将来。
- **影響**: MML StudioのSMF reader/writerやSpessaSynthアダプターは参考/部分移植候補、MMLコンパイラ全体は移さない。

## ADR-002 — Tick と PPQ（決定済み）

- **決定**: Project.ppqはインポート元PPQを保持。レコンポーザ48時間単位は**表示ビュー**で、整数Tickへ勝手に量子化しない。
- **理由**: 96/480/960/1000等のSMF精度とタイミングを維持する。

## ADR-003 — SpessaSynth音源（採用候補、検証必須）

- **決定**: MML Studioと同系列 `spessasynth_lib` + SF2を最優先。Worklet/Sequencer/Seek/Preview/APIは実機・インストール済型定義で検証。
- **制限**: GSデータ保持とGS音声の完全実機一致は別。MIDI機能の公式対応表・SoundFont内プリセットの差を表示。
- **未検証**: 再生中の編集でシームレスにスナップショットを切り替える具体API、複数ポート/GSの実音出力。

## ADR-004 — 外部MIDI OUT（決定済み）

- **決定**: 初版では実装しない。MIDI INは実装し、非対応ブラウザ向けフォールバックを提供。
- **理由**: PC単体で完結する本格MIDI制作を優先。

## ADR-005 — クリップの定義（決定済み）

- **決定**: 初版ではイベントの `EventId` 集合を持つ編集グループ。イベントの正本はTrack.events。境界をまたぐNoteはonsetの側に所属し、クリップ分割では演奏を変えない。
- **今後**: 本格非破壊トリム/テイクコンピングは将来の拡張。現仕様を「DAW風のクリップ操作」に対する制限としてユーザーに説明。

## ADR-006 — ビジュアルモード（決定済み）

- **決定**: トランスポート購読型表示。音声スケジューラとは独立した「ビュー」。FixedCursor / PageTurn / SmoothFollow を提供。単一/複数トラック対応。
- **制限**: レコンポーザの商標やUIをスクリーンショットとして流用しない。数値リスト入力思想に着想を得る独自UI。
- **名称の扱い（2026-11-02 追記）**: 他社の製品名を自分の機能名にしない。UI の表示名は「数値リスト」とし、「レコンポーザ風」は説明（ツールチップ・配色名・README）にとどめる。README に商標の注記を置く。

## ADR-007 — キーボード入力（決定済み）

- **決定**: 通常文字キーが第一級の演奏入力。テンキーは任意。`KeyboardEvent.code`によるJIS/USレイアウト、ユーザー変更可能。数値セルと発音の衝突はフォーカス/入力モードで制御。
- **理由**: テンキーのないノートPCでも制作を完結させる。

## ADR-008 — SMF互換の定義（決定済み）

- **決定**: Format0/1読込、Format1書出し、意味イベントの往復一致を目指す。元バイト列完全一致は対象外。ただしraw Meta/SysEx等を失わない。
- **未検証**: 非典型的な同音重複NoteOn、複数ポートをまたぐSysExとTrackMetaの厳密再生。テストデータで明示。

## ADR-009 — ノートPC対応（決定済み）

- **決定**: テンキーなしで全操作を完結させる。文字キー3×3ドラムパッド、画面パッド、カスタムショートカット、通常キーによるステップ移動。

## ADR-010 — 実装開始時に確認すべきこと（未検証）

1. `https://github.com/cheebow/MMLStudio` の最新 `src/` 構成とコード権利、再利用対象。
2. `spessasynth_lib` と `spessasynth_core` の採用バージョン、APIとライセンス。
3. GeneralUser GSの正確な配布条件、同梱・取得・音源情報UIの要件。
4. 検証ブラウザでのWeb MIDI IN対応（feature detection）。
5. GS Reset / Part Rhythm / Bank Select の具体的なSysEx/音色動作。
6. SMF Meta PortPrefix（FF 21）の保存とSpessaSynth再生時の動作。
7. クリップ操作・同音重複イベント等の端部ケースが仕様とテストで一致するか。

## ADR-010 の確認結果（Phase 0, 2026-11-01）

1. **MML Studio**: ローカル `~/Dev/git/MMLStudio`（commit `a68762c`、作者は本プロジェクトと同じ）。LICENSEファイルは無いが同一作者のため流用可。流用一覧は ADR-013。
2. **SpessaSynth**: `spessasynth_lib@4.4.2`（Apache-2.0、npm最新）。core は ADR-011。API は ADR-012。
3. **GeneralUser GS v2.0.3**（License v2.0）: 個人・商用の制作利用、ソフトへの同梱・改変は自由。条件は「作者のダウンロードファイルへ直リンクしない（自サイトのコピーを配信するか作者サイトへリンク）」。サンプル出所は作者も100%は保証しない旨の記載あり → ライセンス原文を `public/licenses/` に同梱し、アプリ下部からリンク。
4. **Web MIDI**: `navigator.requestMIDIAccess` の有無で機能検出（`src/playback/featureDetect.ts`）。Playwright上の判定: Chromium=あり、Firefox/WebKit の結果は環境依存のため実機で要確認（Phase 6 で再検証）。
5. **GS Reset / Rhythm Part / Bank Select**: 未検証（Phase 7）。SpessaSynth には `synth.systemExclusive(bytes, channelOffset)` があり、SMF経由のSysExも Sequencer が処理する。
6. **FF 21 Port Prefix**: core の `BasicMIDI.portChannelOffsetMap` があり、ポートごとに16chずつオフセットされる設計。実音での独立性は Phase 2/7 で結合試験。
7. 端部ケース: Phase 1 のテストで確認。

## ADR-012 — SpessaSynth API の現物確認（Phase 0, 2026-11-01）

`node_modules/spessasynth_lib/dist/index.d.ts` と `spessasynth_core/dist/index.d.ts` で確認した API:

- 初期化: `new WorkletSynthesizer(ctx)` → `synth.connect(ctx.destination)` → `await synth.isReady`。Worklet は `ctx.audioWorklet.addModule('spessasynth_processor.min.js')`（`scripts/copy-worklet.mjs` が postinstall/predev/prebuild で lib の dist からコピー）。
- 音源: `synth.soundBankManager.addSoundBank(arrayBuffer, 'main')`（ArrayBuffer は転送され detach される）。プリセット一覧は `presetListChange` イベント / `synth.presetList`。
- シーケンサー: `new Sequencer(synth, { skipToFirstNoteOn: false })`、`loadNewSongList([{ binary, fileName }])`（`BasicMIDI` も渡せる）。完了は `songChange`、失敗は `midiError`。`play()` / `pause()` / `currentTime`（setter でシーク、秒）/ `currentHighResolutionTime`（UI用の平滑化時刻）/ `duration` / `paused` / `isFinished` / `playbackRate` / `currentTempo`。
- ループ: `loop` プロパティは無い。`loopCount`（0で無効、`Infinity`で無限）と、core の `BasicMIDI.loop: { start, end }`（**Tick単位**）を使う → Phase 2 で Transport のループ範囲をここへ写す方法を検証する。
- 直接発音: `synth.noteOn/noteOff/controllerChange/programChange/pitchWheel/systemExclusive/stopAll(force)`。各メソッドは `SynthMethodOptions { time }`（AudioContext 時刻で予約）を受け付ける → メトロノームを音声クロックで予約できる見込み（Phase 2 で検証）。
- 複数ポート: `systemExclusive(bytes, channelOffset)`、core の `portChannelOffsetMap`、`channelAdded` イベント。
- **未検証**: 再生中に曲を差し替えたときの位置・発音状態の継続（Phase 2 P11）。
- **検証結果**: Playwright（Chromium headless）で Worklet 読込 → SF2 読込 → デモSMF再生 → 停止がエラーなく完了（`tests/e2e/audio-spike.spec.ts`）。実際に音が聞こえるかは**手動試聴待ち**。

## ADR-014 — 同一 Tick のイベント順序（Phase 1, 2026-11-01）

- **課題**: ARCHITECTURE C は `tick → orderingPolicy → originOrder → id` とするが、読み込んだ SMF の元順と、新規イベントの生成規則（Bank → Program → CC → NoteOff → NoteOn）を同じキーで両立させる必要がある。
- **選択肢**: (A) 全イベントに種類別の優先度を適用 → 読み込んだ曲の同 Tick の順序が変わる（例: Program と CC の順）。(B) 「元順」「生成」のフラグを持たせる → 編集のたびにフラグ管理が必要。(C) `originOrder` 1本で両方を表す。
- **決定**: (C)。読み込みイベントは `originOrder` = ファイル内の順番。新規イベントは `project.nextOriginOrder` から採番し、1回の操作で同じ Tick に作るイベントは生成規則の順に番号を振る（`addEvents` / `policyRank`）。並び順は常に `tick → originOrder → id`。
- **Note Off**: 読み込んだノートは Note Off の元順を `releaseOrder` に持ち、書き出しで元の位置に戻す。長さ・開始位置を変えたノートと新規ノートは `releaseOrder` を持たず、書き出し時は**同じ Tick の他イベントより前**に置く（同音の再発音を誤って止めないため）。
- **互換性影響**: なし（schema 1 の初版）。**検証**: `tests/integration/smf-roundtrip.test.ts`（同 Tick の Note Off / Program / NoteOn、生成 Note Off の位置）、`tests/unit/editing.test.ts`（生成規則の順で書き出し→再読込）。

## ADR-015 — SMF 読み込み時の対応付け（Phase 1, 2026-11-01）

- **2層構造**: `src/core/smf` はバイト列と1対1の低レベル表現（`SmfFile`、全イベントのバイトを保持）。`src/core/project-io/importSmf.ts` / `exportSmf.ts` が `MidiProject` との変換を担う。
- **Format 1 の track 0**: チャンネルメッセージと SysEx が無ければテンポトラックとみなす。テンポ・拍子・調・マーカーは `conductor`、最初の FF 03 は曲名、それ以外のメタ（著作権表示など）は `conductorMeta` に保持し、track 0 に書き戻す。演奏データがあれば通常トラックとして扱う。
- **他トラックのテンポ等**: `conductor` に移し、移動元を通知（I_IMPORT_CONDUCTOR_MERGED）。同じ Tick の異なる値は警告して両方保持。
- **Format 0**: チャンネルごとにトラックへ分割（`Ch n`）。SysEx と非コンダクターのメタは先頭の「System」トラックへ（書き出し時に同 Tick のチャンネルメッセージより前に来る）。書き出しは Format 1。選択肢「1トラックのまま channelOverride で保持」は、DAW 画面でチャンネルごとに編集しにくいため不採用。
- **複数チャンネルが混在するトラック**: 最も多いチャンネルを `track.channel`、それ以外は `channelOverride`。
- **ポート**: 演奏イベントより前の FF 21 を `track.port`（`hasPortPrefix` で再出力）。途中の FF 21 はメタイベントとして保持し警告。再生でのポート切替は未対応（Phase 2/7 で検証）。
- **ノートの対応付け**: チャンネル+音高ごとに古い Note On から順に対応（FIFO）。同音の重なりは警告。長さ 0（同 Tick の On/Off）、対応する On の無い Off、Off の無い On は `RawMidiEvent` として元のバイトのまま保持し警告。どの対応付けでも書き出し時の On/Off の Tick は元と同じになる。
- **文字コード**: FF 03 等は UTF-8 として正しければ UTF-8、そうでなければアプリが渡す Shift_JIS デコーダー（`TextDecoder`）。UTF-8 でなかった名前は元バイトを `sourceName` / `sourceTitle` に保持し、名前を変更しない限りそのバイトで書き出す。
- **ARCHITECTURE C の型への追加**: `MidiProject.conductorMeta` / `nextOriginOrder` / `conductorEndOfTrackTick` / `sourceTitle`、`MidiTrack.endOfTrackTick` / `sourceSmfTrack` / `hasPortPrefix` / `sourceName`、`NoteEvent.releaseOrder`、`TimeSignatureEvent.clocksPerClick` / `thirtySecondsPerQuarter`、`MarkerEvent.rawBase64`。End of Track の Tick も保持して曲末の無音を保つ。
- **未対応チャンク**（MTrk 以外）: 読み飛ばして警告（書き出しには含まれない）。
- **検証**: `tests/unit/import.test.ts`、`tests/integration/smf-roundtrip.test.ts`（12種の自作 SMF で意味的往復一致）。

## ADR-016 — Undo/Redo の実装方式（Phase 1, 2026-11-01）

- **決定**: すべての編集を `MidiProject` の最上位フィールドの浅いパッチ（`Command { label, patch }`）で表す。適用時に旧値を集めて逆パッチを作る。変更のないトラックはオブジェクトを共有するので、履歴は変更されたトラックの旧配列への参照だけを持つ。
- **選択肢**: 操作ごとの逆操作クラス（実装量が多く逆操作のバグが入りやすい）、全体スナップショット（10万イベントで1操作ごとの全体コピーは ARCHITECTURE J に反する）。
- **ドラッグ**: 同じ `mergeKey` の連続コマンドを1ステップに統合（ARCHITECTURE D の「pointerup で1コミット」と併用可）。履歴の上限は既定500（REQ-PRJ-07 は100以上）。
- **値の検証**: 範囲外の値は丸めずに `EditError`。移動は全体の形を保ったまま Tick 0 / 音高 0..127 の範囲内に収める。
- **検証**: `tests/unit/editing.test.ts`。

## ADR-017 — `.midstudio` と IndexedDB（Phase 1, 2026-11-01）

- `.midstudio` = `{ format: 'midi-studio-project', schemaVersion: 1, savedAt, app, project }`。読み込みは JSON 解析 → schema 確認（新しい版は理由付きで拒否）→ 移行チェーン（現在は空）→ 構造検証（ID 重複、範囲、clip が同じトラックのイベントを参照しているか、Base64）→ 設定の不足分を既定値で補完。失敗時は結果オブジェクトでエラーを返し、呼び出し側の曲は変更しない。
- IndexedDB（`src/storage/indexedDb.ts`）は曲を `.midstudio` の JSON 文字列で保存し、ファイル読込と同じ検証を通す。容量不足は `QuotaExceededError` を判別して通知。IndexedDB が無い環境では `unavailable` エラー。自動保存の枠（`autosave`）は用意済みで、UI からの自動保存と復元表示は Phase 3 で接続する。
- **検証**: `tests/integration/project-file.test.ts`（fake-indexeddb）、E2E `tests/e2e/project-io.spec.ts`（Chromium / Firefox / WebKit の実 IndexedDB）。

## ADR-018 — Transport と音源の分担（Phase 2, 2026-11-01）

- **構成**: ARCHITECTURE F の `PlaybackAdapter`（Tick・プロジェクト単位の API）は `src/playback/Transport.ts` が実装する。その下に秒・SMF バイト単位の `PlaybackEngine` インターフェースを置き、`SpessaAdapter` がそれを実装する。Transport は DOM・SpessaSynth に依存しないので、偽エンジンで単体テストできる（`tests/fixtures/fakeEngine.ts`）。
- **位置の正本**: エンジンの曲内時刻（SpessaSynth は `(synth.currentTime − 開始時刻) × playbackRate`、つまり AudioContext の時計）を TempoMap で Tick に変換する。UI は requestAnimationFrame で Transport を読むだけで、独自にカウントしない。曲の終わりは `poll()` で検出（描画中に状態を変えない）。
- **シーク時の状態復元（Chase）**: SpessaSynth の Sequencer はシーク時に `synth.reset()` してから先頭〜目標位置の CC / Program / SysEx / Pitch Bend / RPN をノート無しで再生する（`spessasynth_core` の `setTimeToInternal` を確認）。再生用の Chase はこれに任せる。`src/core/events/chase.ts` は試聴（停止中に鍵盤を押したとき、そのトラックの Bank/Program を先に送る）と検証用。発音中のノートの再発音はしない（ARCHITECTURE F の既定どおり）。
- **ミュート/ソロ**: SpessaSynth のチャンネルミュートは同じチャンネルを共有する別トラックまで消してしまうため使わない。再生用スナップショットを作るときに、鳴らさないトラックのノートだけを除き、CC / Program / SysEx は残す（`buildPlaybackSnapshot`）。切替時は再読み込みし、同じ Tick から再開する。
- **ループ**: `spessasynth_core` の `BasicMIDI.fromArrayBuffer` で解析した曲に `loop = { start, end, type: 'hard' }`（Tick）を設定し、`loopCount = Infinity`。エンジンはループ終端以降のイベントを処理したときに折り返すため、スナップショットのテンポトラックにループ終端の空テキストメタを入れて必ずイベントがあるようにする。`hard` は折り返し時にシークと同じ Chase を行うので、ノートや CC64 が残らない。`BasicMIDI` は lib から値として export されていないため、`spessasynth_core@4.4.3` を直接の依存に追加した（overrides と同じ版）。
- **再生中の編集（P11）**: `setProject` は確定した編集でのみ呼ぶ。再生中なら一時停止 → スナップショット再生成 → 読み込み → 編集前と同じ **Tick** にシーク → 再開。テンポを編集した場合は秒が変わるが、曲中の位置は保たれる。
- **メトロノーム**: SoundFont のチャンネルを使うと曲のドラムと衝突するため、Web Audio の OscillatorNode で鳴らす。25ms のタイマーは先読みを回すだけで、各クリックの開始時刻は `songTimeToContextTime()`（エンジンの曲内時刻から AudioContext 時刻へ）で決める。シーク・ループ折り返しで曲内時刻が戻ったら予約をやり直す。
- **安全策**: 一時停止・停止・SoundFont 切替時に全ボイス停止。ウィンドウのフォーカス喪失・タブ非表示で試聴ノートを解放。
- **未検証**: 複数ポート（FF 21）の実音での独立性、メトロノームとの同期精度の実測、Firefox / Safari での実音（自動テストは Chromium のみ）。
- **検証**: `tests/integration/transport.test.ts`（P01 / P04 / P05 / P09 / P10 / P11）、`tests/unit/chase.test.ts`（P03・メトロノームの拍位置）、E2E `tests/e2e/audio-spike.spec.ts`（Chromium の実エンジンで再生位置の進行、一時停止、ループの折り返し、再生中のミュート/ソロ）。

## ADR-019 — 編集画面の構成（Phase 3, 2026-11-01）

- **共有状態**: `src/app/store/EditorStore.ts` が `MidiProject`・履歴・選択・クリップボード・未保存フラグを1つだけ持ち、トラックビュー・ピアノロール・インスペクター（今後のドラム・リスト・ビジュアルモードも）が同じものを参照する（CLAUDE.md ルール5）。React は `useSyncExternalStore` で購読する。
- **Undo の対象**: 音楽データの編集（ノート・CC・クリップ・トラックの追加削除・名前・ポート・チャンネル・音色）は Undo 対象。ミュート/ソロ/録音待機とループ範囲は保存されるデータなので「未保存」にはするが、DAW の一般的な挙動に合わせて Undo 対象にしない。拡大率・表示パネル・グリッド・選択トラックなどの表示設定は保存されるが、Undo 対象でも未保存扱いでもない（O01 の復元のため `settings` に保存）。
- **音源の再読み込み**: 内容の変更ごとに増える `revision` が変わったときだけ Transport に渡す。表示設定の変更では再読み込みしない。ドラッグ中は画面内のプレビューだけで、確定（pointerup）時に1回だけコマンドを実行する。
- **追従スクロール**（2026-11-01 追記）: 再生中、およびシーク（シークバー・ルーラー）で位置が変わったとき、再生ヘッドが表示範囲の外なら、その小節の頭が左端に来るよう小節単位で切り替える（連続スクロールより読みやすい）。停止中に手でスクロールした表示は戻さない。View →「再生に追従」で無効化できる。
- **描画**: Canvas 2D。静的な層（グリッド・ノート・クリップ）は内容・表示範囲が変わったときだけ描き直し、再生ヘッドは別のオーバーレイ Canvas を requestAnimationFrame で描き直す（曲全体を毎フレーム再描画しない）。表示範囲外のイベントは描かない。10万イベントでの描画性能は Phase 7 で計測する。
- **スナップ**: グリッドは `gridTicks()` で有理数として計算。割り切れない Tick になるグリッド（例: PPQ 1000 の 1/16 三連）はグリッド選択欄に「Tick が割り切れません」と表示し、配置時に丸めた場合は画面に注記する。クオンタイズは確認ダイアログで同意したときだけ丸めて実行する（E08）。Ctrl/⌘ を押しながらのドラッグでスナップを一時無効化。
- **保存操作**: 「ブラウザに保存」（IndexedDB、⌘/Ctrl+S、未保存フラグを解除）、「.midstudio として保存」（ダウンロード）、「MIDI を書き出す」。編集中は 1.5 秒ごとに IndexedDB の自動保存枠へ保存し、次回起動時に復元を提案する（O02）。未保存のまま閉じようとするとブラウザの確認を出す（REQ-PRJ-09。文言はブラウザ固定）。新規・開くの前はアプリ内の確認ダイアログ（`window.confirm` は使わない）。
- **キーボード**: ショートカットは文字入力欄にフォーカスがあるときは無効。⌘/Ctrl+Q・W 等のブラウザ/OS 予約キーは使わない。単独の文字キー（V / P / Q）は Phase 4 の PC 鍵盤演奏モードでは演奏キーを優先する予定（INPUT_RECORDING 7）。
- **未実装の項目**: メニューに無効状態で表示し、理由（実装予定の Phase）をツールチップとメニュー内に表示する。
- **検証**: `tests/unit/editor-store.test.ts`、E2E `tests/e2e/editing.spec.ts`（E01・E10・E03）、`project-io.spec.ts`（C13・O01・O02・O04）、`audio-spike.spec.ts`（P02 を含む）。

## ADR-020 — ドラムエディターと PC キーボード入力（Phase 4, 2026-11-01）

- **ドラムマップ**: GM（35〜81）と GS 追加分（27〜34・82〜87）を組み込み。並び順はキック・スネア・ハイハット・タム・シンバル・パーカッション・効果音（基本キットがスクロールなしで見えるように）。組み込みマップは変更不可で、レーンの非表示・並べ替え・名前変更を行うと曲内に「（カスタム）」のユーザーマップを作り、トラックはそれを参照する（`project.drumMaps`、`track.drumMapId`）。マップに無い音高のノートも「Note n」レーンとして必ず表示し、非表示にしたレーンでも使用中なら表示する（ノートが見えなくならない）。マップ変更でノートの音高は変えない（E09）。レーン間のドラッグだけは移動先レーンの音高へ明示的に変更する。
- **GS 名称**: GS 追加分の楽器名は一般に知られている名称で、実際の音は SoundFont による。公式アドレスマップの検証は Phase 7。
- **入力モード**: `KeyboardRouter`（DOM 非依存）が `edit-shortcuts`（初期状態、キーで音が鳴らない）/ `piano-performance` / `drum-performance` を管理。判定は `KeyboardEvent.code`（物理位置）だけを使い、JIS/US は表示ラベルの切替のみ。テンキーはピアノ演奏に使わないため、PC 鍵盤モードでもテンキーはドラムパッドとして同時に使える（INPUT_RECORDING 3「両方同時に有効」）。同じキーが鍵盤とドラムで同時に鳴ることはない（I02）。
- **衝突回避**: 演奏キーはショートカットより先に判定。演奏モード中は V / P / Q 等の1文字ショートカットを無効化。修飾キー付き（⌘/Ctrl/Alt）は演奏に使わない。文字入力欄・ダイアログにフォーカスがあるときは鳴らさない（I06）。Esc で編集モードに戻る。フォーカス喪失・タブ非表示・モード変更・キー割り当て変更で押下中のノートをすべて離す（I07）。
- **Velocity**: 固定値（既定 100）と Shift 押下時のアクセント（既定 120）。ドラム入力時はドラムマップのレーン既定値を使う。
- **出力先**: 鍵盤入力は選択中のトラック、ドラム入力は選択中のトラックがドラムならそれ、そうでなければ最初のドラムトラック。録音（Phase 6）は `InputController.addSink` に接続する。
- **画面パッド**: パッドは音高で定義し、割り当てられたキー（文字キー / テンキー）をラベル表示する。マウス・タッチでも同じ入力経路（`InputController.padDown`）。
- **キー割り当て**: Tools →「キー割り当て」でスロットごとに物理キーを変更（Esc / Space / Tab / Enter / 修飾キーは不可）。別のマップと重なる場合は警告。保存はプロジェクトの `inputPresets`（O01 で復元）。
- **画面サイズ**: 1280×720 でドラムエディターのレーンとパッドが見えるよう、ツールバーを1行・レーン高さを抑えた。
- **未検証（手動）**: 実機の JIS / US キーボードでの位置、NumLock OFF 時のテンキー（ブラウザが `code` を `Numpad1` 等で返す前提。自動テストは `code` 指定のみ）、キーボードのゴースト（同時押しの上限）、ノート PC での3〜4和音。
- **検証**: `tests/unit/keyboard-router.test.ts`（I01〜I07 の入力判定、E09 のマップ）、E2E `tests/e2e/drum-input.spec.ts`（E02 / E09 / I02 / I03 / I06・画面パッド・キー割り当て）を Chromium / Firefox / WebKit で実行。

## ADR-021 — リストエディターとビジュアルモード（Phase 5, 2026-11-01）

- **行の計算**: `src/core/list/listRows.ts`。MEAS は TimeSignatureMap の小節、STEP は同じ小節内の表示順（`STEP` と `ST` は別物）、ST は**同じトラックの全イベント**の時刻順で次のイベントまでの Tick（フィルターで隠したイベントも数える）、GT はノート長。最後のイベントの ST は「--」。ドラムトラックの詳細欄はドラムマップの楽器名。
- **編集**: ST の変更は後続イベントをすべて差分だけ移動（リップル、E05）。GT はそのノートの Note Off だけ（E06）。TICK 列は絶対位置の変更（その1行だけ移動して並べ直し）。VEL 列はノート Velocity / CC 値 / Program（UI 1〜128）/ Pitch Bend / Pressure。Classic 48 表示での入力は整数 Tick に正確に戻せる値だけ受け付け、割り切れない値は理由を示して中止（丸めない）。
- **フィルター**: 種類ごとに表示を切り替えられる。フィルター中は行頭に「+n」（間に隠れているイベント数）を表示し、**数値の編集はすべて拒否**する（UI_DESIGN 6.1「数値編集は全件表示でのみ許可」に従い、ST 以外も一律に禁止）（E12）。
- **キーボード操作**: ↑↓ 行（Shift で複数選択）、←→ / Tab 列、Enter / F2 / 数字キーで編集開始、Enter 確定（次の行へ）、Esc 取消、Delete 削除、Home / End / PageUp / PageDown。編集中のセルは文字入力欄なので PC 鍵盤・ドラム演奏は鳴らない（I06）。選択はピアノロール・ドラムと共有。
- **仮想化**: 表示範囲の前後5行だけを DOM に描画（10万行を作らない）。
- **テンポトラック**: リストの横に表示のみ（テンポ・拍子・調・マーカー）。テンポ・拍子の編集 UI は Phase 7 で検討（データモデル・書き出しは対応済み）。
- **ビジュアルモード**: `src/ui/visual/VisualMonitor.tsx`。全画面オーバーレイの表示専用ビューで、開閉しても再生に触れない（P02）。現在行は Transport の Tick から二分探索で求め、**同じ Tick の行をすべて**ハイライト（P06）。各ペインは同じ Transport 位置を読む（P07）。Fixed Cursor（現在行を上から 1/3 に固定）/ Page Turn（画面単位で切替）/ Smooth Follow（表示だけを補間。位置の正本は Transport）。表示位置は現在行だけから求めるので、シーク・ループ・停止で即座に再同期する（P08）。長い休符では「次のイベントまで」を表示。React の再描画は現在行・ページが変わったときだけで、時計と Smooth のスクロールは DOM に直接書く。
- **表示設定**: 分割（1 / 左右2 / 上下2 / 4）、ペインごとのトラック、追従方式、配色（レトロ青 / 緑 / モダン）、単位、文字サイズは表示設定として曲に保存（O01。データ上のキーは `settings.tm`）。全画面は Fullscreen API（ユーザー操作時のみ）。ペインにミュート / ソロ外を表示（REQ-PLAY-05）。T キーまたはツールバーの「TM」で開閉、Esc で閉じる。
- **未実装**: カウントインの表示（Phase 6 で録音と一緒に実装）、全トラック巡回表示（UI_DESIGN 7 で後続拡張とされている）。

## ADR-022 — 録音（Phase 6, 2026-11-01）

- **共通の入力経路**: PC 鍵盤・テンキー・画面パッド・Web MIDI はすべて `InputController` で `CapturedInput`（note-on/off・CC・Pitch Bend・Pressure、`atMs` は `performance.now()` 系の時刻）に正規化し、試聴と録音（`addSink`）に同じイベントを渡す（INPUT_RECORDING 1）。
- **時刻→Tick**: 入力の `timeStamp`（KeyboardEvent / MIDIMessageEvent）を、その瞬間の Transport の曲内時刻（音源エンジンの AudioContext 時計）から逆算して曲内秒に変換し、TempoMap で Tick にする（`LiveTake`）。`Date.now()` は使わない。録音中にテンポが変わっても TempoMap で正しく変換される（I10）。レイテンシ補正は ms 単位で前にずらす（I15）。精度は入力イベントの時刻と描画フレームの差に依存し、実測は未実施（手動試聴項目）。
- **録音先**: R（録音待機）のトラック。鍵盤入力はメロディ用、ドラム入力（ドラムパッド / ドラムモード）はドラム用の待機トラックへ。どちらかが複数ある、または待機トラックが無い場合は録音せず理由を表示（INPUT_RECORDING 1）。
- **モード**: オーバーダブ / 置き換え（録音範囲、パンチ時はパンチ範囲の既存ノート・CC 等を削除。SysEx・メタ・raw は残す）。パンチ: ループ範囲を流用し、範囲外の入力は記録せず、範囲をこえるノートはパンチアウトで切る。ループ録音: 時刻が戻ったら次のテイクにし、ループ終端をまたいで押されていたノートは終端で閉じる。「すべて重ねる」か「最後のテイクだけ」を選ぶ（テイクの自動評価はしない）。録音クオンタイズは既定オフ（設定でグリッドに合わせる。割り切れないグリッドでは行わない）。
- **1回の Undo**: 停止時に全トラック分の変更を1つのコマンドにまとめる。押されたままのノートは停止位置で閉じて通知。CC64 はノート長に反映せずイベントとして記録（I12）。
- **カウントイン**: 0 / 1 / 2 / 4 小節。クリックは AudioContext 時刻で予約し、終了後に再生を開始する。カウントイン中の入力は記録しない。再生開始の数 ms の揺れは記録データに影響しない（録音位置は Transport の位置から求めるため）。
- **曲の終わりをこえる録音**: SpessaSynth のシーケンサーは最後の「発音系イベント」で止まる（メタイベントは数えない）ため、録音中は `EngineSong.minEndTick` で `lastVoiceEventTick` を延長し（`Transport.setTail`）、空の曲にも録音できるようにした。これを入れる前は、空の曲で録音すると全ノートが Tick 0 に記録される不具合があった（E2E で発見）。
- **ステップ録音**: `StepController` と `src/core/recording/stepRecorder.ts`。カーソルはピアノロール・ドラムエディター共通（緑の破線）。鍵盤は同時に押した音を和音として、すべて離したときに入力して進む。ドラムは押すたびに現在位置へ入力し、既定は自動で進まない（同じ位置にキック＋ハイハット等を重ねる、I09）。音長は Tick が割り切れるグリッド値のみ。ゲートは音長の %。操作は通常キー（→ 休符・次へ、← 戻る、- タイ、Backspace 直前を取消）と画面ボタンで完結し、テンキーの + / − も使える（テンキーなしで完結、CLAUDE.md ルール6）。
- **Web MIDI**: `MidiInputAdapter`。ユーザー操作から `requestMIDIAccess({ sysex: false })`。機器一覧・有効/無効・受信チャンネルの絞り込み・受信チャンネルをそのまま記録するか（既定は録音先トラックのチャンネル）。抜き差しは `statechange` で反映し、切断・無効化した機器で押されていたノートは離して録音側も閉じる（I14）。非対応ブラウザ・許可拒否では理由を表示し、他の機能はそのまま使える（I13）。Program Change の受信は記録しない。
- **PC 鍵盤のサステイン**: ツールバーの「Sus」とメニューで CC64 のオン/オフ。
- **未検証（実機）**: 外部 MIDI キーボードでの録音・抜き差し（擬似 MIDIAccess での自動テストのみ）、Firefox / Safari での録音、入力レイテンシの実測。
- **検証**: `tests/unit/recording.test.ts`（I08〜I12・I15）、`tests/unit/midi-input.test.ts`（I13・I14、擬似デバイス）、`tests/integration/recording-flow.test.ts`（入力経路→録音→1回の Undo、ステップ録音）、E2E `tests/e2e/recording.spec.ts`（テンキーなしのステップ入力、MIDI 設定画面、Chromium 実エンジンでの PC 鍵盤リアルタイム録音とカウントイン）。

## ADR-023 — GS 詳細と品質（Phase 7, 2026-11-01）

- **GS SysEx の解釈範囲**: Roland DT1（`41 dev 42 12 addr×3 data sum F7`）でチェックサムが正しく、データ 1 バイトで、`GS_PARAMS` にあるアドレスだけを意味付きにする。アドレス表は公開資料と、組み込みの `spessasynth_core@4.4.3` の `rolandSystemExclusive` の実装で照合し、表のすべてが内蔵音源で処理されることも確認した（`engine: true`）。Delay・EFX・ドラムマップ個別・複数バイトのデータは解釈しない（16 進表示・16 進編集のみ）。チェックサムの合わないメッセージは解釈せず、バイトも変更しない。
- **値の編集**: 意味付きの項目は値の変更時にだけバイト列を作り直し、チェックサムを再計算する（デバイス ID は元の値を維持）。16 進編集は 0x80 以上のバイトを途中に置けない検証のみ。
- **リズムパート**: 読み込み時に「Use for Rhythm Part」（値 > 0）のチャンネルのトラックをドラム表示にする。ポートはその SysEx があったトラックのポートとみなす（デバイス ID とポートの対応は検証していない）。インスペクターから Ch10 以外のドラムトラック用に挿入できる。
- **GS Reset**: メニューから明示的に最初のトラックの Tick 0 へ挿入し、そのトラックの Tick 0 の他のイベントより前に置く（`originOrder` を最小値 −1 にする。負の値も許容）。既にある場合は挿入しない。
- **Bank / Program・ミキサー・ベンド幅**: すべて Tick 0 の実イベントとして書く（UI の値だけを保存して SMF に出ない、ということを避ける：UI_DESIGN 8）。Bank/Program は既存の Tick 0 の CC0 / CC32 / Program を置き換え、Bank → Program の順に作る。ミキサーは既存の Tick 0 の CC を書き換え、無ければ追加。ドラッグ中は試聴用に CC を送るだけで、離したときに 1 回だけ記録する。
- **テンポ・拍子の編集**: リストのテンポトラック欄で BPM（内部は整数 µs）と拍子を編集・追加・削除。Tick 0 のテンポ・拍子は削除不可。
- **ライセンス**: 配布物に含まれるランタイム依存（React 系 MIT、spessasynth_lib / core・stb-vorbis Apache-2.0、fflate MIT）と GeneralUser GS のライセンス原文を `public/licenses/` に同梱し、`THIRD_PARTY.md` に一覧化。
- **性能**: `docs/PERFORMANCE.md`。
- **静的配布**: `BASE_PATH=/リポジトリ名/ npm run build` で GitHub Pages 等のサブパスに対応。SoundFont は `npm run fetch-soundfont` でビルド前に取得して `dist/` に含める（作者サイトへの直リンクはしない）。CI 設定ファイルは作成していない（ユーザーの公開手順に合わせて追加する）。
- **検証**: `tests/unit/gs.test.ts`、E2E `tests/e2e/gs-quality.spec.ts`（GS 表示・編集、E13、ミキサー、テンポ、2 ポートで音源チャンネル 32 以上、性能）。

## ADR-024 — 試用フィードバックへの対応（2026-11-01）

ユーザーの試用で出た指摘に対応した。

- **トラックビューの縦スクロール**: トラック名の列とレーンが縦に連動せず、多数のトラックで下のトラックが見えなかった。キャンバスを表示範囲の高さにし、縦スクロール量でレーンを描画、トラック名の列も同じ量だけ動かす。ルーラーは上に固定。トラック名の上のホイールでもスクロールする。
- **高さ調整・折り畳み**: 上下の領域の区切り線をドラッグで調整、ダブルクリックまたは ▾ で下部エディターを折り畳み、タブのクリックで再表示。ピアノロール / ドラムの下のコントローラーレーンも同様。高さと折り畳み状態は表示設定（editorHeight / editorCollapsed / laneHeight / laneCollapsed）として曲と一緒に保存し、Undo 対象・未保存扱いにはしない（ADR-019 の表示設定と同じ）。区切り線にフォーカスして ↑↓ / Enter でも操作できる。
- **録音中のノート表示**: 録音中は LiveTake.preview() で確定済みのノートと押下中のノート（現在位置まで伸ばす）を毎フレーム取り出し、ピアノロール・ドラムエディター・トラックビューのオーバーレイに赤で描く。プロジェクトへの反映は従来どおり停止時に1回（Undo 1回で戻せる）。
- **ビジュアルモードの見た目**: ユーザーが示したレコンポーザの画面写真に合わせ、「レコンポーザ風」配色を既定にした（黒地・水色の文字、緑の列見出し、SONG / TR. のタグ、+ PLAY + 表示、現在行は白い反転バー、同じ Tick の残りの行は黄色）。小節番号は小節の最初の行だけ、STEP は同じ Tick のグループの先頭だけ「n:」（和音の2音目以降は「:」）、音名は「A 4」形式、ST が 0 の行は空欄、小節の区切りに「:-------」行（ST 欄に小節長）。右側に大譜表を描き、鳴っている音を点で表示（現在行の音は白、同じ Tick の他の音は黄、前から鳴っている音は水色）。調号があれば ♯ / ♭ の数を表示。製品のロゴ・画面画像は使わず独自の描画で再現（ADR-006 の制限は維持）。フォントは外部から読み込まず端末の等幅フォントを使う。従来の配色も選択できる。
- **表示の乱れ**: MIDI 入力の設定・録音の設定で、チェックボックス付きの行が縦並びのレイアウトに巻き込まれていた。チェックボックス行だけ横並びにした。
- **検証**: tests/unit/list.test.ts（ビジュアルモードの表示行）、tests/unit/recording.test.ts（録音中プレビュー）、E2E tests/e2e/editing.spec.ts（高さ調整・折り畳み、トラック名とレーンの連動スクロール）。録音中の赤いノートの描画そのものは自動テストでは確認しておらず、実機での確認が必要。

## ADR-025 — トラックの並び順（2026-11-01）

- **決定**: MIDI ファイルの読み込み時、トラックをポート → チャンネルの順（A1〜A16、B1〜）に並べる。同じポート・チャンネルのトラックはファイル内の順を保つ（安定ソート）。`openMidiFile(…, { trackOrder: 'file' })` でファイル順のままにもできる。既存の曲は Track メニュー「チャンネル順に並べ替え」（Undo 可）。新しいトラックは空いているチャンネル（Ch10 を除く）を割り当て、チャンネル順の位置に入れる。
- **理由**: ユーザーの要望。チャンネル単位で曲を把握しやすい。
- **空のトラック**（2026-11-01 追記）: 演奏データの無いトラックはチャンネルが既定値（Ch1）でしかないため、チャンネル順に混ぜると先頭に来てしまう。SysEx だけのトラック（GS Reset 等の初期設定）は先頭、演奏データのあるトラックはポート → チャンネル順、空またはメタイベントだけのトラックは末尾（ファイル順のまま）とした。
- **互換性影響**: 書き出す SMF のトラックの順番が元ファイルと変わることがある。各トラックのイベントと Tick は変わらず、意味的往復比較（C13）は通る。同じ Tick で別トラックにあるイベントの処理順は再生側の実装に依存する点は従来と同じ。
- **検証**: `tests/unit/editing.test.ts`（track order by channel）。

## ADR-026 — ミキサーの見た目と操作（2026-11-01）

- **決定**: DAW のミキサー画面を参考に、トラックごとの縦長のチャンネルストリップにした。上から色帯とトラック番号・名前、音色名、つまみ4つ（Pan / Reverb / Chorus / Expression、2×2）、縦フェーダー（Volume、0〜127 の目盛り）、数値、M / S / R、ポート・チャンネル。つまみはリアルな質感を避けた単純な円＋指針＋弧（Pan は中央から左右に弧を描く）。ミュート中・ソロ外のストリップは色を薄くする。
- **操作**: つまみは上下ドラッグ（Shift で細かく）、フェーダーはつまみがポインターに追従（トラックの高さ＝0〜127）し、トラックのクリックでその位置へ移動。どちらもホイール・矢印 / PageUp / PageDown / Home / End、ダブルクリックで初期値（Volume 100、Pan 中央、Reverb 40、Chorus 0、Expression 127）。ARIA の slider として読み上げ・キーボード操作できる。
- **データ**: 従来どおり（ADR-023）、動かしている間は試聴用に CC を音源へ送り、操作を終えたときに Tick 0 の CC を1回だけ記録（Undo 1回）。未設定の項目は CC を書き込まず、薄く表示する。
- **検証**: E2E `tests/e2e/gs-quality.spec.ts`（つまみ・フェーダー・ダブルクリックが Tick 0 の CC として書き出されること）。

## ADR-027 — 音源オブジェクトの生成とドラムトラックの統合（2026-11-01）

- **「音源が読み込まれていません」が出る不具合**: 音源の表示は「読み込み済み」なのに、再生すると古い文言（「音源を起動」を押す）のエラーが出た。SoundFont の読み込みを遅くして再生・Space・読み込み直後の再生を試しても再現しなかった。開発サーバーの React Fast Refresh で `useMemo` の中のエンジン（SpessaAdapter / Transport / EditorStore 等）が作り直され、画面の状態（音源読み込み済み）だけが残ったことによる食い違いと判断した（推定。開発中のみ起こる）。対策: エンジン類は `useState` の初期化で1回だけ作る。再生ボタンは常に「音源の準備を確認してから」再生する。古い文言を変更。
- **ドラムトラックの統合**: 楽器ごとに MTrk が分かれた曲（BD / SD / HH …、すべて Ch10）を読み込むと、同じポート・同じチャンネルのドラムトラックを1つの「Drums」トラックにまとめる（`openMidiFile(…, { mergeDrums: false })` で無効化可）。既存の曲は Track メニュー「同じチャンネルのドラムトラックをまとめる」（Undo 可）。イベントの ID・Tick・元の順序（originOrder）は保持するので、同じ Tick ではファイル内のトラック順が保たれ、意味的往復比較は変わらない。トラック名の FF 03 は統合後のトラック名に置き換わる（各楽器名はドラムマップで表示）。ポートが違うトラックはまとめない。チャンネルが違うトラックを手動でまとめる場合は、各イベントに元のチャンネルを `channelOverride` で残す。
- **検証**: `tests/unit/editing.test.ts`（merging drum tracks: 読み込み時の統合、意味的往復一致、統合しないオプション、メニュー操作と Undo）。
- **コントローラーだけのトラック**（2026-11-01 追記）: ノートが無く CC / Pitch Bend / Pressure だけのトラック（例: MELO_MOD・MELO_BEND）は、読み込み時に同じポート・チャンネルでノートを持つ最初のトラックにまとめる（`mergeControllers: false` で無効化可）。ノートを持つトラックどうし（ハモリパート等）は別パートの可能性があるため自動ではまとめず、Track メニュー「同じチャンネルのトラックをすべてまとめる」（Undo 可）で行う。ユーザー提供の vision.mid / xmas.mid で、読み込み → 書き出しの意味的差分が 0 件であることを確認。

## ADR-028 — 試聴の音色・ドラムの色・拍線・メニュー（2026-11-01）

- **MIDI キーボード / PC 鍵盤の試聴の音色**: 停止中の試聴では「再生位置より前」の Bank / Program だけを送っていたため、最初の Program Change が曲の途中にあるトラックではピアノのまま鳴っていた。再生位置より前に Program Change が無い場合は、トラックの最初の Program Change（インスペクターに表示している音色）とその前の Bank Select を送る（`firstSoundMessages`）。
- **ドラムの色**: 楽器のグループごとに色相（キック 赤、スネア 橙、ハイハット 黄、タム 緑、シンバル 水色、パーカッション 紫、効果音 桃）、同じグループ内は音高で明度をずらす（`src/ui/drumColors.ts`）。ドラムエディターの記号、レーン名の色見本、画面パッド、Velocity レーンの棒に使う。選択中は太い枠で示し、塗りは楽器の色のまま。
- **拍線**: ピアノロールとドラムエディターで、グリッド線（細く薄い）・拍の線（中間）・小節線（2px で濃い）の3段階にした。
- **メニュー**: 無効な項目の理由を右側に表示していたため、狭い幅で項目名が1文字ずつ折り返されていた。項目名は折り返さず、理由はツールチップ（title）と `aria-description` に移した。メニューが画面より長い場合は縦スクロールする。
- **検証**: `tests/integration/transport.test.ts`（audition uses the track sound）、`tests/e2e/smoke.spec.ts`（無効理由のツールチップ）。色・線の見た目はスクリーンショットで確認。

## ADR-029 — 再生位置に追従するミキサー / インスペクター、試聴専用シンセ（2026-11-01）

- **ミキサー**: Tick 0 の CC だけを見ていたため、途中にある値（例: Tick 489 の CC7）や、曲中の変化（CC11 のフェードアウト、CC10 のオートパン）が反映されなかった。再生位置で有効な CC（再生位置以前で最後のもの、無ければトラック最初のもの）を表示し、再生中は追従する（`controllerAt`）。動かすと表示中のイベントを書き換え、その CC が無いときだけ Tick 0 に追加する（`setControllerAt`）。曲中で変化する CC には「A」（オートメーション）の印と、個数のツールチップを付ける。
- **インスペクターの音色**: 同様に、再生位置で有効な Program Change（と、その時点の Bank Select）を表示・編集する（`programAt` / `setProgramAt`）。編集はそのイベントを書き換え、Bank Select も同じ Tick に Bank → Program の順で置く。何小節目のイベントか、トラック内の個数を表示する。ミキサーの音色名も同じ値を使う。
- **試聴専用シンセ**: SpessaSynth のシーケンサーは、ループの折り返し・シーク・曲の再読み込みのときにシンセ全体のボイスを止め（`sendMIDIAllOff` → `stopAll`）、hard ループやシークではさらに `synth.reset()` する（spessasynth_core 4.4.3 の `jumpToTick` / `setTimeToInternal` を確認）。そのため、MIDI キーボードで弾いている音がループの折り返しで途切れていた。試聴（MIDI キーボード・PC 鍵盤・パッド・鍵盤クリック）は同じ AudioContext 上の2つ目の WorkletSynthesizer で鳴らし、曲の再生とノート管理を完全に分けた（ARCHITECTURE F）。試聴のたびに、そのトラックの再生位置での Bank / Program / CC を試聴用シンセに送る（再生中も）。ミキサー操作中の CC は両方のシンセに送る。Panic は両方を止める。
- **代償**: SoundFont を2つのシンセに読み込むため、メモリ使用量が増える（GeneralUser GS で数十 MB 程度の増加を想定。未計測）。
- **ドラッグの確定**: ピアノロール・ドラム・トラックビューのドラッグ状態を ref にも同期して持ち、pointerup では常に最新の値を使う（素早く離すと最後の移動が反映されないことがあった。Firefox の E2E がまれに失敗したことから判明）。
- **検証**: `tests/unit/gs.test.ts`（mixer follows the playhead / inspector sound follows the playhead）、`tests/integration/transport.test.ts`（separate preview synth）。ループの折り返しで MIDI キーボードの音が途切れないことは**手動確認待ち**。

## ADR-030 — 起動時の自動開始と初期設定欄（2026-11-01）

- **背景**: ブラウザは音を出す前にユーザー操作を求め（自動再生ポリシー）、Web MIDI は初回に許可が必要。完全な自動化はできない。
- **決定**: 起動時に (1) AudioContext の開始を試し、実行状態になれば（ブラウザがそのサイトでの自動再生を許す場合）そのまま音源を有効にする、(2) `navigator.permissions.query({ name: 'midi' })` で MIDI の許可状態を調べ、許可済みなら確認なしで接続する。どちらかが残る場合は、ツールバーの下に非モーダルの「初期設定」欄を出し、「開始」1回で音源の開始と MIDI の許可要求をまとめて行う。「MIDI は使わずに開始」を選ぶと、その選択を localStorage に保存して次回は聞かない（ARCHITECTURE I: 小さな UI 設定は localStorage 可）。画面のどこかのクリックでも音源は開始する（従来どおり）。
- **非モーダルにした理由**: 開いたままでも編集を始められ、操作をふさがない。
- **最初の操作で MIDI も**（2026-11-01 追記）: まだ許可していない場合、画面への最初のクリック / キー操作で音源の開始と同時に MIDI の許可も求める（「MIDI は使わない」を選んでいない場合）。メニューから設定を開かなくても、一度許可すれば次回から自動で接続される。
- **新規プロジェクトの音色**: 最初のトラックの Tick 0 に Program Change 0（GM Acoustic Grand Piano）を入れ、Track メニューで追加したトラックにも同じものを入れる（追加と同じ1回の Undo）。読み込んだ MIDI ファイルには何も足さない。
- **ブラウザ差**: Permissions API の `midi` が無いブラウザでは「未許可」とみなして欄を出す。Web MIDI 非対応ブラウザでは「使えません（PC キーボードで演奏できます）」と表示。
- **検証**: E2E `tests/e2e/smoke.spec.ts`（初期設定欄の「開始」で音源が有効になること）。実ブラウザでの自動開始の可否はサイトの利用状況でブラウザが決めるため、自動テストでは確認できない。

## ADR-031 — ビジュアルモードの表示の追加（2026-11-01）

- **決定**: ビジュアルモードの表示を3つから選べるようにした（保存データの設定キーは互換性のため `settings.tm` のまま）。
  - **レコンポーザ**: 従来の演奏追従リスト（ADR-021 / ADR-024）。
  - **ピアノロール**: 全トラックのノートをトラック色で描き、固定した再生ヘッド（左から 22%）の下を流す。表示範囲は6小節、音域は曲全体の最低〜最高音。鳴っているノートは白枠で強調、ミュート / ソロ外は薄く表示。
  - **鍵盤**: MML Studio のチャンネルモニター（同じ作者）の構成を参考に、トラックごとに音色・Vol / Exp のバー・Pan / PB の位置・レベル（鳴っている音の最大ベロシティ）・全音域の鍵盤（鳴っている鍵がトラック色で光る）。コードは MIDI Studio のデータ（Tick・トラック・CC の時系列）に合わせて新規に書いた。
- **性能**: `src/core/visual/monitorData.ts` で、プロジェクトの変更時にトラックごとのノートと Vol / Exp / Pan / PB / Program の時系列を作り、毎フレームの参照は二分探索で行う（曲全体を毎フレーム走査しない）。描画はそのビューの Canvas だけを毎フレーム更新。
- **音色の表示**: トラック自身に Program Change が無い場合は、同じポート・チャンネルの他のトラックの Program Change を使う（実際にその音色で鳴るため）。
- **検証**: `tests/unit/monitor-data.test.ts`、E2E `tests/e2e/list-visual.spec.ts`（3つの表示の切り替え、鍵盤表示で Tick 0 の和音が光ること）。

## ADR-032 — トラックビューのクリップ削除と右クリックメニュー（2026-11-01）

- **背景**: ユーザーから次の要望があった。トラックビュー（上のビュー）では削除できない。選択中のオレンジ枠が何を表すのか分かりにくい。DAW のリージョンのような扱いがほしい。右クリックでもいろいろ操作したい。
- **決定**:
  1. クリップ（＝リージョン）を選ぶと、ノートの選択を解除する。この状態で Delete を押すと、クリップを中のノートごと削除する（1 クリップ = 1 Undo）。Edit → 削除 も、クリップだけを選んでいるときに使える。
  2. クリップの上端に、名前（未設定ならトラック名）を書いたヘッダー帯を描く。オレンジ枠は「選択中のクリップ」を表す。
  3. 右クリックメニュー `useContextMenu`（`src/ui/menu/ContextMenu.tsx`）を追加した。
     - 閉じる条件: Esc、外側のクリック、ホイール、ウィンドウのフォーカス喪失。
     - 項目の形はメニューバーと同じ（`MenuItem`）。
     - 対象: トラックビューのクリップと空き部分、ピアノロールとドラムのノートと空き部分、リストの行。
     - 編集操作は `EditActionsContext` を通して、Edit メニューと同じ関数を呼ぶ。
     - macOS の Ctrl+クリックも右クリックとして扱う（`isSecondaryClick`）。描画やドラッグは始めない。
  4. クリップの名前と色は `updateClip` で変更する。クリップ情報は `.midstudio` に保存され、SMF の出力は変わらない。
- **見送った案**: クリップの端をドラッグして長さを変える機能。ADR-005 の「クリップを縮めてもノートは切らない」方針と、端の外に出たノートをどのクリップに属させるかの規則を先に決める必要があるため、今回は入れない。代わりに「ここで分割」と「クリップだけ解除」を提供する。
- **互換性**: プロジェクトファイルの形式は変わらない（`clip.name` と `clip.color` は既存の任意フィールド）。
- **検証**:
  - unit: `updateClip` は SMF の出力を変えず、Undo できる。
  - E2E（3 ブラウザ）: クリップを選んで Delete すると削除され、Undo で戻る。右クリックからの複製と削除。Esc でメニューが閉じる。ピアノロールの右クリックで移調、コピー、ここへ貼り付け、削除。

## ADR-033 — テンポと拍子の変化を表示する（2026-11-01）

- **背景**: ユーザーから「テンポや拍子の変化が分かるように表示したい」という要望があった。これまで、テンポと拍子はトランスポートバーの現在値と、リストエディターのテンポトラックでしか確認できなかった。
- **決定**:
  - トラックビューのルーラーの下に、高さ 26px の「テンポ」レーンを設ける。
    - テンポは段差の線で描く。上下はその曲のテンポの最小値から最大値に合わせる。テンポがすべて同じなら中央の 1 本の線になる。
    - 変化点に BPM を書く。ラベル同士が重なりそうなときは書かず、線の段差だけで示す。
  - 拍子の変化は、ルーラーの小節番号の横に紫のラベルで示す。
  - ピアノロールとドラムエディターのルーラー（高さ 20px）には、拍子（紫）とテンポ（橙）のラベルを小節番号の後ろに並べる。
  - 表示する変化は `conductorMarks` で抜き出す。値が前と同じ重複イベントは変化として扱わない。同じ Tick に複数あるときは最後のイベントを採る（TempoMap と同じ）。
  - トラックの縦位置は `HEAD_H = 24 + 26` だけ下がる。
- **見送った案**:
  - テンポレーンのグラフをドラッグして編集する機能は入れていない。テンポを変えると Tick と秒の対応が変わり、録音済みの演奏の聞こえ方にも影響するので、値を数値で入力するリスト編集を正本のままにする。
  - キー（調号）とマーカーの表示は、今回は入れていない。
- **互換性**: データと SMF には影響しない（表示だけの変更）。
- **検証**: unit で、変化の抜き出し、同じ Tick の扱い、BPM の書式を確認した。E2E のトラックビューの座標を新しいヘッダーの高さに合わせて更新した。スクリーンショットでテンポ 120→140→96.5→100、拍子 4/4→3/4→6/8 の表示を目で確認した。

## ADR-034 — 演奏中の編集で再読み込みを 1 回にまとめる、マーカーと調号の表示、ミキサーの A 印の配置（2026-11-01）

- **不具合**: 演奏中にミキサーのパンなどを動かすと、演奏が途中で止まったり、曲の頭に戻ったりした。
  - **原因**: 再読み込みの間、`getPosition()` は `parkedTick` を返す。ところが、再生を始めてから一度も一時停止していないと、この値は古いまま（多くは 0）だった。再読み込み中に次の編集が来ると、その古い位置から再開していた。加えて、ホイールで動かすと 1 段ごとに確定するので、再読み込みが何回も続いていた。
  - **修正**:
    1. 再読み込みを始めるときに、`parkedTick` を再開する位置にする。
    2. 演奏中の編集は 150ms 待ってからまとめて 1 回だけ再読み込みし、そのときに再生している位置から再開する。待っている間に一時停止・停止したら再読み込みは取り消し、次の再生で読み込む。シークしたら、その場で再読み込みしてシーク先から再開する。
    3. 再読み込みが終わるまではエンジンは編集前の曲を演奏しているので、位置の計算には読み込み済みの曲のテンポマップ（`engineTempo`）を使う。
  - **検討した別案**: CC の編集だけは再読み込みせず、エンジンへ直接送る案。曲の中に同じ CC のイベントが残っていると、ループやシークのときに古い値に戻ってしまうので採らなかった。
  - **検証**: integration テストを 3 件追加した。連続した編集で読み込みが 1 回になり位置を保つこと、読み込み中の編集でも頭に戻らないこと、一時停止で待機中の再読み込みを取り消すこと。実際の音源での試聴は未確認。
- **マーカーと調号**:
  - 曲にマーカーがあるときだけ、トラックビューに高さ 18px の「マーカー」レーンを出す。マーカーのない曲では画面の高さを使わない。
  - 調号は `Key F` や `Key Em` の形で、小節番号の横に表示する。
  - ピアノロールとドラムエディターのルーラーには、テンポ・拍子・調号・マーカーをすべて表示する。
- **ミキサーの A 印**: これまでは、つまみのラベル（REVERB など）の後ろに置いていた。そのためラベルが折り返し、チャンネルごとに高さがずれていた。A 印をつまみの右上隅に絶対配置にして、レイアウトに影響しないようにした。🥁 の入るチャンネル表示も高さを固定した。

## ADR-035 — 調号に合わせた音名の表記と、大譜表の調号の位置（2026-11-01）

- **要望**: 「調号が分かるなら大譜表にも出せるか。その場合、左のリストの # と b はどう表示するのか」。
- **決定**:
  - **大譜表**: 調号の ♯ / ♭ を、楽譜で決まっている位置に置く（ト音記号では ♯ が F5 C5 G5 D5 A4 E5 B4、♭ が B4 E5 A4 D5 G4 C5 F4。ヘ音記号はその 2 オクターブ下）。音符の臨時記号は、調号に含まれていれば付けず、調号を打ち消すときは ♮ を付ける（`spellPitch`、従来どおり）。
  - **リスト**（ビジュアルモードの左側とリストエディター）: 実際に鳴っている音の名前をそのまま書く。調号によって省略はしない。黒鍵の書き方だけを調に合わせ、♭ 系の調では `Bb4` のように b で、それ以外は `A#4` のように # で書く。リストは 1 行だけ見ても音高が分かることを優先した。
  - **ドラムトラック**: 鳴るのは楽器なので、調に関係なく常に # で書く。
- **見送った案**: リストでも調号にある臨時記号を省く案。行だけを見て音高を判断できなくなるので採らなかった。また、E♯ や C♭ のような白鍵の異名同音は使わない（F 、B と書く）。
- **検証**: unit で、調ごとの音名と、曲の途中の転調に追従することを確認した。F・D・E♭ 長調のスクリーンショットを撮り、調号の位置、臨時記号が省かれること、リストの表記を確認した。

## ADR-036 — 演奏中のミキサー操作で再読み込みしない、出力レベルメーター（2026-11-01）

- **不具合**: つまみを回してから少し待って手を離すと、再生が一瞬途切れた。ADR-034 で再読み込みを 1 回にまとめても、確定したときの 1 回の再読み込み（一時停止 → 読み込み → 再開。読み込みのときに音を止める）は残っていた。
- **決定**: ミキサーの値は、動かしている間にすでに音源（シーケンサー側にも）へ送っている。そこで、確定でできた曲データについては `transport.deferReloadFor(project)` を使い、演奏中は再読み込みしない。
  - 書き換える CC は、再生位置で有効になっているイベント（再生位置より前）か Tick 0 に追加するイベントなので、このまま演奏を続けても古い値がもう一度鳴ることはない。
  - 古い値が鳴り直す可能性があるのは、ループの折り返しとシークのとき。そのときに再読み込みする（`poll` で位置が戻ったことを検知する）。一時停止・停止の後の再生では、通常どおり読み込む。
  - 再読み込みを遅らせるのは、`deferReloadFor` で渡したプロジェクトのときだけ（同一オブジェクトかどうかで判定）。ほかの編集はこれまでどおり再読み込みする。
  - **制限**: ループの折り返しのときの再読み込みでは、一瞬途切れる可能性がある。
- **レベルメーター**: SpessaSynth の `connectChannel(node, ch)`（チャンネル別の可視化用出力）を AnalyserNode につなぎ、毎フレームのピーク値を -48〜0 dBFS で表示する。
  - 上がるときはすぐに追従し、下がるときはゆっくり下げる。
  - React の再描画を使わず、要素のスタイルを直接書き換える。
  - シーケンサー用とプレビュー用の両方のシンセをつなぐ。
  - 出力は 16 系統しかないため、ポート B 以降は同じチャンネル番号のメーターと合算になる（ツールチップと UI_DESIGN に記載）。
  - **検討した別案**: ノートのベロシティから計算する MIDI メーター。実際の音量（CC7、CC11、エンベロープ）を反映しないので採らなかった。
- **検証**:
  - integration: 遅らせた変更では読み込みが起きないこと、ループの折り返しとシークで再読み込みすること、通常の編集では再読み込みすること。
  - E2E（Chromium、実際の音源）: 再生中にメーターが上がること、再生中にパンを動かしても止まらず頭にも戻らないこと。
  - 耳で聴いて途切れないかどうかは、まだ確認していない。

## ADR-037 — テンポトラックの編集画面と、テンポチェンジの入力方法（2026-11-01）

- **背景**: ユーザーから「テンポチェンジを入れるのに、リスト横のテンポトラック欄は使いにくい」という指摘があった。この欄は再生位置に今のテンポを複製するだけで、追加した後に値を書き換える必要があった。位置も変えられなかった。
- **決定**:
  - 下のエディターに「テンポ」タブ（`TempoEditor`）を追加した。テンポ・拍子・調号・マーカーを時刻順の 1 つの一覧にまとめ、位置と値をその場で編集できる。リストエディターのテンポトラック欄は廃止し、「テンポトラックを開く」ボタンに置き換えた。
  - 追加と変更は、core の `upsertConductorEvent(project, tick, value, id?)` に一本化した。値と位置を 1 回の Undo で変える。
    - 同じ種類のイベントを同じ Tick に置くと、前のものを置き換える（テンポ・拍子・調号は Tick ごとに 1 つ）。マーカーは同じ Tick に複数置ける。
    - 拍子は、編集中のイベントを除いた拍子マップで計算した小節の頭に寄せる。
    - 拍子イベントが持つ SMF の FF 58 の 3・4 バイト目は、変更しても保持する。
  - 位置の入力は `TimeSignatureMap.parse`（`format` の逆変換）で行う。「5」「5.2」「5.2.240」「005.02.240」の形を受け付ける。
  - 入口を 3 か所に増やした。
    - トラックビューのテンポレーン・マーカーレーン・ルーラー: 右クリックメニューとダブルクリック。近く（7px 以内）に変化点があれば変更、なければ追加。
    - レーンの見出しのクリック: 「テンポ」タブを開く。
    - トランスポートバーの BPM と拍子の表示: クリックでメニューを開く。
  - Tick 0 のテンポや拍子も削除できるようにした。削除した場合は、SMF の既定値（120 BPM、4/4）として扱う。以前の記録（Phase 7）では「削除不可」としていたので、方針を変更した。
- **見送った案**: テンポレーンの線をドラッグして値を変える操作。録音済みの演奏の秒数が変わるため、うっかり動かしやすい操作は避けた（ADR-033 と同じ理由）。
- **検証**:
  - unit: 追加、位置と値の同時変更、同じ Tick での置き換え、拍子の小節頭への寄せ、不正な値の拒否、位置の解析。
  - E2E（3 ブラウザ）:
    - テンポタブで小節と BPM を指定して追加し、その場で位置・値を変え、削除する。拍子とマーカーの追加も確認した。
    - テンポレーンの右クリックで追加し、ダブルクリックで変更する。見出しのクリックでタブが開く。
    - BPM 表示のクリックで、有効なテンポを変更する。

- **追記（2026-11-02、試聴のフィードバック）**: タブ名「テンポ」は中身（テンポ・拍子・調号・マーカー）と合わず分かりにくいという指摘で、タブと各所の呼び名を「コンダクター」「コンダクタートラック」に統一した（SMF の Track 0 の一般名で、データモデルの `conductor` とも一致する。仕様書の「テンポトラック」は同じものを指す）。一覧には「表示:」の種類ボタン（件数つき）を足し、テンポだけ・マーカーだけのように絞り込めるようにした（コンポーネントの状態だけで保存しない）。行の「▶ここへ」は意味が伝わらなかったので「再生位置にする」にし、右クリックメニューの「再生位置をここへ」「貼り付け（ここへ）」も「再生位置をここに移動」「ここに貼り付け」に改めた。E2E `tempo.spec.ts` に絞り込みと「再生位置にする」を追加。

## ADR-038 — 再読み込み中の一時停止・停止・シークを優先する（2026-11-02）

- **背景**: Fable 5.1 による設計レビュー（ADR-018 / 034 / 036 の Transport まわり）で、曲の読み込み中（`loading`）に届いた操作が、読み込み完了時に上書きされることが分かった。偽エンジンの読み込みを手動で完了させるテストで再現した。
  1. 再生中の編集で再読み込みが始まってから一時停止（Space）すると、読み込み完了時に `resume` フラグで再生が再開してしまう。
  2. 読み込み中にシークすると、読み込み完了時に再読み込み開始時の位置へ戻ってしまう。
- **決定**: `Transport.reload` は、読み込み完了後に「開始時に受け取った値」ではなく、そのときの `parkedTick`（シークで更新される）と `resumeAfterLoad`（一時停止・停止で false になる）を使う。読み込み中は `getPosition()` が `parkedTick` を返すので、UI の表示と再開位置が一致する。
- **互換性影響**: なし。**検証**: `tests/integration/transport.test.ts`「pause / seek while a reload is in progress」（`SlowEngine` で読み込みの完了を遅らせる）。実機での試聴は未確認。

## ADR-039 — 演奏中の編集の扱いを内容で判定する、Undo 履歴の容量上限、自動保存のタイミング（2026-11-02）

Fable 5.1 のレビューで挙がった 4 点への対応。

- **演奏中の編集（ADR-034 / 036 の置き換え）**: これまでミキサーは「この曲オブジェクトは再読み込みしなくてよい」と `deferReloadFor` で Transport に伝えていた（同一オブジェクトかどうかで判定）。間に別の更新が挟まると普通の再読み込みに戻る壊れやすい仕組みだったので、Transport が**編集の内容**を見て決めるようにした（`classifyPlaybackChange`、`src/core/project-io/playbackDiff.ts`）。
  - **none**: 再生用スナップショットが変わらない編集（クリップ名・色、トラック名・色、表示設定）は何もしない。これまではクリップ名の変更でも再読み込み（音の途切れ）が起きていた。
  - **live**: 変更・追加・削除がすべて再生位置以前の CC の値だけなら、Transport がその CC の「再生位置で有効な値」を両方のシンセへ送り、エンジンは走らせたままにする。ミキサーだけでなく、リストエディターやコントローラーレーンで確定した CC の編集も途切れなくなる。Bank Select・Data Entry・RPN/NRPN・チャンネルモード（CC120〜127）は対象外。削除で有効な値が無くなる場合は再読み込み。
  - **reload**: それ以外（ノート・音色・テンポ・ループ・ミュート/ソロ・トラック設定・再生位置より後の CC）は従来どおり 150ms まとめて再読み込み。
  - ミキサーの `deferReloadFor` 呼び出しは削除した。
- **ループの折り返し（ADR-036 の制限）**: live で送った値は、折り返し時にエンジンの古い曲がチェイスで古い値に戻す。古い（変更前の）イベントがループ開始より後に無ければ、折り返しを検知した時点で値を送り直すだけにし、再読み込みしない（ミキサーの Tick 0 の値など、ほとんどの場合）。ループ内に古いイベントが残る場合だけ再読み込みし、その際は**ループ開始位置から**再開する（以前は検知時の位置から再開していたため、ループ先頭の音が読み込み時間ぶん欠けていた）。1 フレーム（16ms 程度）だけ古い値が鳴る可能性は残る。
- **Undo 履歴の容量**: 1 回の編集は触ったトラックのイベント配列を作り直すため、履歴 1 件がその配列（イベント 1 個あたり 8 バイトの参照）を保持する。実測: 3,150 イベントのトラックで 1 件 26 KB（500 件で 13 MB）。10 万イベントが 1 トラックに集まる曲では 1 件 800 KB・500 件で 400 MB になりうる。そこで履歴に「保持イベント数の上限」（既定 200 万個 ≒ 16 MB）を設け、超えたら古い件から捨てる。ただし REQ-PRJ-07 のとおり**直近 100 件は必ず残す**（1 トラック 10 万イベントの曲でも 100 件 ≒ 80 MB で頭打ち）。件数の上限 500 はそのまま。
- **自動保存**: 10 万イベントの曲の JSON 化は実測 47 ms（17 MB）。編集の 1.5 秒後に即実行していたのを `requestIdleCallback`（上限 2 秒、非対応ブラウザでは従来どおり）で空き時間に回し、再生中の UI の引っかかりを減らす。音声は AudioWorklet 側で動くので、音には影響しない。
- **見送った案**: 履歴をイベント単位の差分で持つ（Undo の仕組みを作り直す必要があり、パッチ方式の単純さを失う）。自動保存の Worker 化（構造化クローンのコストが JSON 化と同程度で、効果が薄い）。
- **検証**: `tests/unit/playback-diff.test.ts`（none / live / reload の判定）、`tests/integration/transport.test.ts`（live 送信・折り返しの再送・ループ内に古いイベントがあるときの再読み込み位置・none で再読み込みしないこと）、`tests/unit/editing.test.ts`（容量上限で古い件が消え、直近 100 件は残ること）、E2E `gs-quality.spec.ts`（Chromium 実エンジンで、再生中のパン操作で止まらないこと）。**手動試聴（2026-11-02、ユーザー）**: 再生中にミキサーを動かしても途切れず、ループの折り返しも問題なし。

## ADR-040 — コントローラーレーンの選択、クリップの長さ変更、トラックの並べ替え、選択に追従する録音待機（2026-11-02）

ユーザーの試聴で挙がった 4 点への対応。

- **CC / Pitch Bend レーンの選択**: これまでポイントは「クリックで値をドラッグ、Alt+クリックで削除」だけで、選択に入らなかった。Delete で消せず、複数のポイントをまとめて扱えない。ポイントもほかのイベントと同じ `selection.eventIds` に入れる（ピアノロール・リストと共通の選択、CLAUDE.md ルール 5）。クリックで選択、Shift で追加・解除、空いているところのドラッグで枠選択、選択をドラッグで値をまとめて変更（グループの形を保つため、範囲を超えない分だけ動かす）。削除は Delete / Alt+クリック / 右クリックメニュー。
  - 枠選択は描画で間引かれたポイント（1px に複数ある場合）も含めて選ぶ。密な Pitch Bend をまとめて消す用途に合わせた。
  - 空いているところの「クリックで追加」は残す。クリックとドラッグの区別は 3px の移動で行う。
- **クリップの長さ変更**（`resizeClip`）: 端のドラッグで範囲だけを変える**非破壊**の操作にした。ノートは動かさず、切らない（UI_DESIGN 3「イベントの発音を勝手に切断しない」）。範囲から出たイベントはクリップから外れてトラックに残る（「クリップだけ解除」と同じ状態）。範囲に入った、どのクリップにも属さないイベントは `createClip` と同じ規則でクリップに入る。MIDI の内容は変わらない。
  - **見送った案**: 範囲外のノートを削除・短縮する破壊的トリム。DAW によってはそうだが、Undo 前提でも「端を少し動かしたらノートが消えた」事故が起きやすく、分割と同じく非破壊を優先した。必要なら後で「範囲外のノートを削除」をメニューに足せる。
- **トラックの並べ替え**（`moveTrack`、既存の `reorderTracks`）: トラックヘッダー左端のハンドル（⋮⋮）の上下ドラッグ（6px 動いたらドラッグ開始、挿入位置に線）と、Track メニューの「上へ移動／下へ移動」（Alt/Option+↑↓）。ピアノロールのフォーカス中は Alt 付きの↑↓を移調に使わないようにした。並べ替えは Undo 対象。再生中は再読み込み扱い（スナップショットのトラック順が変わるため）。
- **選択に追従する録音待機**（`RecordingSettings.armFollowsSelection`、既定オフ）: オンにすると、トラックの選択が変わったときにそのトラックだけを Arm にする。録音先があいまいにならず（INPUT_RECORDING 1）、R を押し忘れない。`EditorStore.updateSettings` の中で行い、どの画面からの選択でも同じに振る舞う。Arm は保存データなので未保存扱いにするが、Undo 履歴には入れない（ミュート／ソロと同じ）。既定をオフにしたのは、既存の操作（R を押す）を変えないため。古い `.midstudio` には項目が無いので、読み込み時に既定値で補う。
- **互換性影響**: `.midstudio` のスキーマ番号は変えない（設定の追加のみ、欠けていれば既定値）。SMF の入出力に変更なし。
- **検証**:
  - unit: `tests/unit/editing.test.ts`（`resizeClip` の縮小・拡大・他クリップのイベント除外・不正範囲・Undo・MIDI 不変、`moveTrack` の端での停止・Undo）、`tests/unit/editor-store.test.ts`（追従オン／オフ、同じトラックの再選択、未保存フラグ、Undo 履歴に入らないこと）。
  - E2E（3 ブラウザ）: `editing.spec.ts`（Pitch Bend レーンのクリック選択・枠選択・Delete・Undo、クリップの端のドラッグでノートが動かず範囲外のノートがクリップから外れること、ヘッダーのドラッグと Alt+↓ の並べ替えが書き出した SMF に反映されること）、`recording.spec.ts`（追従オンで選択したトラックだけが Arm になること、設定が保持されること）。
  - 手動（2026-11-02、ユーザー）: ハンドルからの並べ替え・端での自動スクロールを含めて「いい感じ」と確認。密な Pitch Bend の描画は未確認。
- **追記（2026-11-02、試聴のフィードバック）**: ヘッダー全体をドラッグ対象にしていたところ、「薄くなったまま動かない」ことがあった。名前の文字からドラッグを始めるとブラウザの文字選択・ネイティブドラッグと競合し、pointerup が届かないケースがあると判断し、次のように変えた。(1) ドラッグ開始はハンドル（⋮⋮）だけにし、pointerdown で `preventDefault`、ヘッダーは `user-select: none`。(2) 終了は pointerup / pointercancel / lostpointercapture に加えて window の pointerup・blur でも行い、Esc で取り消す（薄い表示が残らない）。(3) 一覧の上下 24px で止めると rAF で自動スクロールし、挿入位置は実際の scrollTop から計算する（いちばん下からいちばん上へも動かせる）。E2E: ハンドル以外からはドラッグが始まらないこと、上端で自動スクロールして先頭に置けること、Esc で取り消せること。

## ADR-041 — メニューの階層化（2026-11-02）

- **背景**: Edit に移調が 4 項目、View にエディター 5 つと拡大縮小 4 項目、MIDI に入力モード 5 項目が平らに並び、「メニューを整理して階層化したい」という指摘があった。

- **互換性影響**: なし。E2E のヘルパー `menu()` に `sub` 引数を追加。

## ADR-042 — 総点検（Fable 5.1 によるレビュー）で見つかった不具合の修正（2026-11-02）

UI 側とコア／再生側を分けてコード全体を読み直し、確認できた不具合を直した。設計判断を含むものだけここに残す（細かい修正はコミット「総点検」を参照）。

- **再読み込み中の編集の取りこぼし（Transport）**: 停止・一時停止から `play()` した読み込みの途中で編集が確定すると、`setProject` は「再生中ではない」経路で位置を記録するだけで、読み込みは開始時の曲のまま再生を始めていた（偽エンジンで再現: ミュートしたトラックが鳴る）。`reload()` の最後に「読み込み開始時の曲」と「今の曲」を比べ、再生用スナップショットが変わらなければ `loaded` を更新、変わっていて再生中なら追いかけの再読み込みを 1 回入れる。あわせて、後方シークやライブ送信の直後の `poll()` がループの折り返しと誤認しないよう `lastPolledTick` を更新する。
- **巨大な配列への `Math.max(...spread)`**: 12 万イベント前後で V8 の引数上限により `RangeError` になり、`openMidiFile` が結果ではなく例外を返していた（上限は 100 万イベントのはず）。`maxOf` / `minOf`（`src/core/model/numbers.ts`）に置き換え、15 万イベントの取り込みをテストに足した。
- **Tick の上限を 1 つにする**: 編集・検証は 2^40、SMF の VLQ は 0x0FFFFFFF で、間の値は保存はできるが書き出し・再生で例外になっていた。上限を `SMF_LIMITS.maxTick = 0x0FFFFFFF`（480 PPQ で 77 時間以上）に統一し、ノートは終端も上限内であることを要求する。
- **取り込みが受け付けるものは保存形式も受け付ける**: 範囲外の調号（±8 以上）や拍子（分子 0）を取り込むと、`.midstudio` に保存した後で開けなくなった。取り込み側で範囲外は raw メタとして保持する（捨てない）。テストで `validateProject` が空であることを確認する。
- **表示設定の検証は「既定値に戻す」**: 古い・手で編集した `.midstudio` の設定（NaN のズーム、グリッド 0、存在しないトラック ID、未知の列挙値）はファイルを拒否せず項目ごとに既定値へ戻す（`sanitizeSettings`）。曲データ本体の検証は従来どおり厳格。
- **インスペクター／ミキサーの編集がクリップから外れる**: Program / Bank / 先頭 CC を書き換えると、新しいイベントがクリップに属さなくなり、クリップの移動・削除に付いてこなかった。置き換え元が属していたクリップ（無ければ位置を含むクリップ）に入れる。
- **UI**: ダイアログ・メニューの中ではグローバルショートカット（Space / Delete / ⌘Z / Esc など）を無効にする。自動保存の復元は未保存の曲を上書きする前に確認し、別の曲を開いたら案内を消す。ページを閉じる・隠すときに自動保存を即時に書く。ピアノロールの ⌘+ホイールはネイティブの非 passive リスナーで処理する（React 経由では `preventDefault` が効かずページも拡大していた）。トラック名の変更で Enter が二重に確定・Esc が確定してしまう競合を直す。無効なサブメニュー親は開かない。すべてのキャンバスとスプリッターで `pointercancel` を扱い `touch-action: none` を付ける。録音開始時に `transport.play()` が失敗したら REC 状態を解除する。ベロシティレーンの塗り対象をドラッグ開始時に決める。クリップのダブルクリックは右クリックメニューと同じ編集画面を開く。ミキサーのノブ／フェーダーは描画時の state ではなく ref から値を確定する（同日の別コミット）。さらに、矢印キーの連打やホイールの刻みが React の再描画より速く届くと、描画時の値を起点に同じ値を計算して 1 段しか進まないことがあった（WebKit の E2E で時々 68 にならない）。刻みの起点も ref にした。
- **ビジュアルモードの分割を戻したときの表示崩れ（同日、試聴のフィードバック）**: 上下 2 分割から 1 画面に戻すと、譜表のキャンバスが半分の高さのまま残った。`fitCanvas` がインラインの `style.width / height` で大きさを固定するため、CSS（`width: 28%; height: 100%`）で大きさが決まるキャンバスは、レイアウトが変わっても元の大きさに留まっていた。`fitCanvas` に `cssSized` を足し、ビジュアルモードの 3 つのキャンバス（譜表・全トラックのピアノロール・鍵盤）ではインラインの大きさを書かない。E2E `list-visual.spec.ts` で分割→1 画面の後に譜表の高さがペインの高さと一致することを確認する。
- **見送ったもの**: SMF 内の F1〜FE ステータスや長さが 3 でない FF 51 は、現状どおり理由つきのエラーで取り込みを中止する（黙って捨ててはいない。raw として保持するには SMF 側のイベント型を増やす必要があり、実ファイルでの要望が出てから）。`play()` が読み込み失敗時にも resolve する挙動（P10）はそのまま。
- **検証**: `tests/integration/transport.test.ts`（読み込み中の編集、後方シーク＋ライブ編集）、`tests/unit/import.test.ts`（15 万イベント、範囲外メタの往復）、`tests/unit/editing.test.ts`（Tick 上限、`addTrack` のイベント、`duplicateClip` の位置）、`tests/unit/gs.test.ts`（クリップ所属）、`tests/integration/project-file.test.ts`（設定の既定値への復帰）。E2E 3 ブラウザ全件。
- **リファクタリング（同日）**: 重複していたコードを共通化した。`useSignatureMap`（11 か所の `new TimeSignatureMap(...)`、うち 2 か所は毎描画で作り直していた）、`useDragState`（4 つのエディターの ref ミラー）、`useElementSize`（ResizeObserver）を `src/ui/hooks.ts` に、`selectedTrack(project)` を `src/core/model/selectedTrack.ts` に、`IS_MAC` / `MOD_LABEL` を `src/ui/platform.ts` にまとめた。コンテキストメニューはメニューバーと同じ `MenuList` を描くようにし、項目の描画・無効時のツールチップ・キーボード操作を一本化した（サブメニューも使える）。残る候補: `App.tsx`（1,100 行超）のメニュー定義・ダイアログ・音源起動の分離、3 エディターの再生ヘッド用 rAF ループの共通化。
- **ビジュアルモードの操作列（同日、試聴のフィードバック）**: 表示の切り替え・表示設定・再生／全画面／戻るが一列に混ざり、セレクトにラベルがなく、全体が半透明で無効に見えた。役割ごとに 3 群へ分けた: 再生操作（状態表示、⏮ ■ ▶）／表示切り替えとその表示専用の設定（分割・追従・単位にラベル）／見た目（配色・文字）と画面操作（全画面、← DAW に戻る）。半透明をやめ、戻るボタンを右端で強調した。


## ADR-043 — クオンタイズダイアログ（音符・強さ・シャッフル・長さ）（2026-11-02）

- **背景**: クオンタイズは Q キー／メニューで編集グリッドに位置を揃えるだけだった。「16 分のクオンタイズはそのままでよいが、ダイアログで音符や長さやシャッフルを選んで適用したい」という要望。
- **決定**: 2 段構えにする。(1) Q と「クオンタイズ（1/16）」は従来どおり編集グリッドで位置だけを即時に揃える。(2) ⇧Q と「クオンタイズ…」はダイアログ（`src/ui/editing/QuantizeDialog.tsx`）で、対象（選択中のノート / 選択トラックの全ノート。選択が無ければトラック）、音符（1/1〜1/64 × 通常・3 連符・付点。編集グリッドとは独立）、強さ（0〜100%）、シャッフル（50〜75%）、長さ（変えない / 終わりもグリッドへ / グリッドの倍数に揃える）を選んで適用する。
- **コア**: `QuantizeOptions` に `swing` と `lengthGrid` を追加。シャッフルは `snapTickSwing`（`src/core/timing/grid.ts`）で、2 グリッドを 1 組として偶数番目の線を `pair × swing%` の位置に置く DAW 流の定義（50 = なし、66.7 ≈ 3 連符、75 = 付点）。長さは `round(長さ / グリッド)` 倍、最短 1 グリッド。強さは位置（と「終わりも」のときは終端）の差分に比例。ダイアログの値は `settings.quantize` としてプロジェクトに保存し（`sanitizeSettings` で範囲外は既定値へ）、次回も同じ値で開く。
- **丸めの扱い（ADR-002 との整合）**: Q の経路は従来どおり、Tick で割り切れないグリッドは確認してから丸める。ダイアログは強さ 100% 未満やシャッフルで必ず丸めが起きるため、`allowRounding: true` で実行し、その旨と「1 グリッド = n Tick（割り切れない場合はその注意）」をダイアログに常に表示する。黙って丸めることはしない。
- **見送った案**: プレビュー（適用前に音を聴く）と範囲（グリッド線から遠いノートを除外する感度）。ランダム化（ヒューマナイズ）は引き続き未実装。
- **追記（2026-11-02）**: トラックビューのクリップ（リージョン）の右クリックにも「クオンタイズ（グリッド）」「クオンタイズ…」を足した。クリップの中のノートを選択してから同じ操作を呼ぶだけで、クリップの選択は保つ。ノートの無いクリップでは無効（理由をツールチップに）。E2E `context-menu.spec.ts`。
- **互換性影響**: `.midstudio` の `settings.quantize` が増える（無ければ既定値）。`quantizeEnds` は維持。
- **検証**: `tests/unit/editing.test.ts`（`snapTickSwing`、強さ・シャッフル・長さ、設定→オプションの対応、割り切れない長さグリッドの拒否）、`tests/integration/project-file.test.ts`（設定の既定値への復帰）、E2E `editing.spec.ts`（ダイアログで 1/8＋長さを揃えて適用、Undo 1 回、値が保存され ⇧Q で開く）。

## ADR-044 — DAW 風の 1 文字ショートカットと、入力モードの切り替え UI（2026-11-02）

- **背景**: ショートカットは V / P / Q / T / R と修飾キーつきだけだった。「各種 DAW のようなショートカットも使いたいが、ソフト鍵盤とぶつからないように切り替える UI が必要」という要望。PC 鍵盤モードでは文字キーが音になるため、1 文字ショートカットは本質的に排他である（INPUT_RECORDING 7）。
- **決定（ショートカット）**: 編集モードだけで働く 1 文字キーを足す。Enter / Home 先頭へ、`,` `.` 1 小節戻る / 進む（小節の頭へ）、Shift+Space 選択ノートの先頭から再生、L ループ ON/OFF、Shift+L 選択範囲を小節単位でループに、I / O ループの始点 / 終点を再生位置のある小節に、M / S 選択トラックのミュート / ソロ、K メトロノーム、J スナップ、F 再生に追従、1〜5 エディタータブ、Shift+Q クオンタイズダイアログ。Logic / Cubase / Studio One で共通性の高いものを選び、ブラウザ予約（⌘T / ⌘W / ⌘L / Alt+D など）は避けた。物理位置で決めるもの（`,` `.` 1〜5）は `code` で判定し JIS / US で同じ場所にする。Enter はボタン・タブ・リンクにフォーカスがあるときは奪わない（そのボタンの実行が優先）。
- **決定（切り替え UI）**: ツールバーの `<select>` を「編集 / 鍵盤 / パッド / ステップ ▾」のセグメント（`src/app/InputModeSwitch.tsx`）に替え、各ボタンにキー（Esc / ⌥K / ⌥P）を小さく併記する。鍵盤・パッド中はステータスバーに「文字キーは演奏に使用中。1 文字のショートカットは無効（Esc で編集へ）」と出す。キーボードからは ⌥K（PC 鍵盤 ⇄ 編集）、⌥P（ドラムパッド ⇄ 編集）。Alt / Option つきのキーは `KeyboardRouter` が演奏に使わないので、演奏中でも切り替えられる。ステップ入力の 2 種はセグメントの「ステップ ▾」から選ぶ（ドラム以外のトラックで「ステップ（ドラム）」を選ぶと注記を出す）。
- **見送った案**: 1 文字ショートカットを演奏モードでも「Shift つきなら有効」にする（Shift はアクセントのベロシティに使っている）。モード切替を 1 つのキー（例: Tab）でトグルにする（Tab はフォーカス移動と競合）。ズーム（⌘+ / ⌘−）はブラウザの拡大と衝突するため見送り。
- **互換性影響**: E2E ヘルパー `setInputMode()` を追加し、`input-mode-select` を使っていたテストを置き換えた。メニューの「ミュート / ソロ / 再生に追従 / 入力モード」にキー表記が付く。

## ADR-045 — ツールバーの 2 段化と、画面上の拡大・縮小ボタン（2026-11-02）

- **背景**: 1 段のツールバーにトランスポートと入力モードの切り替えが並び、「別の段にしてもいいのかも」という指摘。拡大・縮小は表示メニューと ⌘+ホイールだけで、画面上から操作できなかった。
- **決定**: ツールバーを 2 段にする。1 段目はトランスポートだけ（シークバーが広く取れる）。2 段目は左に「入力」ラベル＋モードのセグメント＋Oct− / Oct+ / Sus、右に音源の状態と「ビジュアル」。拡大・縮小は、トラックビューはトラックヘッダー列の上（ルーラーの高さの空き）に、ピアノロール／ドラムエディターはツール列のグリッド選択の右に − / + を置く。倍率の刻み（1.25 倍）と上下限は `src/ui/zoom.ts` にまとめ、メニューとボタンで共有する（⌘+ホイールは従来どおり 1.15 倍刻みの連続操作）。
- **見送った案**: ズームスライダー（刻みの方が ⌘+ホイールと役割が分かれて分かりやすい）。縦方向のズーム（要望が出てから）。
- **互換性影響**: なし。E2E はトラックヘッダー列の上端が従来と同じ高さ（24px）になるよう `box-sizing: border-box` で固定。

- **追記（2026-11-02、ズームの基準点）**: 拡大・縮小で左端の Tick を保っていたため、見たい場所が流れた。`useZoomAnchor`（`src/ui/hooks.ts`）で、⌘+ホイールはポインターの下の Tick、ボタン／メニューは画面中央の Tick がその場に留まるよう scrollLeft を合わせる（曲頭の余白もズームに追従するので式に含める）。トラックビュー・ピアノロール・ドラムエディター共通。E2E `smoke.spec.ts`。

## ADR-047 — カウントイン中の早押しは開始位置に揃える（2026-11-02）

- **背景**: リアルタイム録音で 1 小節目の少し手前に弾いたノートが捨てられていた。`Recorder.capture` が録音フェーズ以外の入力を無視していたため。「補正するか、はみ出しても編集できるようにしてほしい」という要望。
- **決定**: カウントインの**最後の 1 拍**（最後のクリックから開始まで）に入った入力は、開始位置（録音を始めた Tick。曲頭なら Tick 0）の時刻として LiveTake に渡す。ノートの終わりは通常どおり実時間から求めるので、長さはほぼ保たれる。それより前の拍に入ったノートオンは、このテイクのための音とは考えにくいので記録せず、停止時のメッセージで「開始位置に揃えた数」「記録しなかった数」を伝える。録音の設定ダイアログにも同じ説明を置く。

- **見送った案**: 許容幅の設定（まず 1 拍固定で様子を見る）。カウントインなしのとき、再生開始前に弾いた音は従来どおり開始位置に揃う（位置が止まっているので自然にそうなる）。
- **互換性影響**: なし。
- **検証**: `tests/integration/recording-flow.test.ts`（偽タイマーでカウントイン 1 小節: 最後の拍の note-on が Tick 0 に、1 拍目の note-on は記録されない、メッセージに件数）。

## ADR-048 — 再生中のノート編集は停止・シーク・ループ折返しで反映する（2026-11-02）

- **背景**: 再生中にノートを動かすと再生がガタガタになる。エンジン（SpessaSynth のシーケンサー）は曲の SMF スナップショットを鳴らしており、ノートの編集はスナップショットの再読み込みを要する。読み込み直しの瞬間に鳴っている音が止まり、位置を合わせて再開するため、ドラッグやベロシティ塗りのように編集が続くと途切れも続く（ADR-039 の 150ms のまとめでは足りない）。「再生中はいじれない仕様にするのもあり」という相談に対し、編集はできるが音への反映を遅らせる案を選んだ。
- **決定**: 再生中の `reload` 判定のうち、内容の編集（ノート・音色・テンポ／拍子・再生位置より後の CC・トラックの並び・曲の終端）は**再読み込みしない**。エンジンは鳴らしている曲のまま、次の停止／一時停止→再生、シーク、ループの折り返し（ループ開始位置から読み直す）で新しい曲を読み込む。`Transport` の `deferredStale` / `staleInLoop` の仕組み（ADR-039 の live 編集用）をそのまま使い、`TransportState.pendingEdits` でトランスポートに「変更は停止後に反映」と出す。即時に反映するもの（`IMMEDIATE_RELOAD`）: 最初の読み込み、PPQ、ループ範囲の変更、ミュート／ソロ・ポート／チャンネル（track settings）、トラックの増減。これらは操作として「今すぐ聞きたい」ものなので短い途切れを許容する。再生位置以前の CC は従来どおり値を直接送り、途切れない。
- **見送った案**: (1) Transport が自前でイベントを予約してシンセに送る DAW 方式（途切れずに即反映できるが、シーケンサーを使わない再生系を作る大きな作業。要望が強ければ別途）。(2) 再生中は編集を禁止する（制約が強い割に得るものが同じ）。(3) 設定で即時／遅延を選べるようにする（まず遅延のみで様子を見る）。
- **互換性影響**: `TransportState` に `pendingEdits` が増える。P11 のテスト（再生中の編集で再読み込み）は内容の編集では「再読み込みしない」に、即時の例としてループ範囲の変更を使うように書き換えた。
- **実機で見つかった落とし穴**: ブラウザでは、ノートを置いた直後にループ開始位置へ飛んだ。SpessaSynth の時計は poll ごとに Tick の 1/50 程度だけ戻ることがあり、ループ折返しの判定（`tick < lastPolledTick`）がそれを折返しと誤認して、遅延中の編集をループ開始から読み直していた。判定に 1/16 音符ぶん（PPQ/4）の許容を入れた。ADR-039 の live 編集では値の再送だけだったので目立たなかった。
- **検証**: `tests/integration/transport.test.ts`（ノート編集は再読み込みせず位置が進み続ける、停止→再生で新しい曲、ループ折返しでループ開始から読み直す、シークで読み直す、ミュートは即時、読み込み中の内容編集も遅延、Tick 未満の時計の揺れは折返しにしない）。E2E は既存の再生テストで回帰確認。Chrome の実エンジンで、ループ再生中にノートを置いても位置が飛ばず「変更は停止後に反映」が出て、折返しで反映されることを確認。

## ADR-057 — 複数クリップの選択とグループ操作（2026-11-02）

- **背景**: ピアノ・ベース・ギター・ドラムの 4 トラックに入れた 2 小節を丸ごと後ろに複製したい。クリップは 1 つずつしか選べず、コピー／貼り付けはノートだけだった。
- **決定**: トラックビューで Shift（⌘ / Ctrl）+クリックでクリップをトグル選択、Shift+ドラッグで範囲選択（Tick × トラック行の矩形に重なるクリップ）。空いているところの右クリックに「この位置のクリップを全トラックで選択」。選択中のクリップにドラッグ（移動）・⌥ドラッグ（複製。トラックのずらしも一括）・⌘C / ⌘X / ⌘V / ⌘D / Delete が効く。クリップボードは `ClipboardData.clips`（元トラック・相対位置・名前・色・イベント）を持ち、`events` には全イベントを平らに入れるので、ノートエディターの「ここに貼り付け」は同じクリップボードをノートとして貼れる。貼り付けは各クリップを元のトラックへ（無くなっていれば選択トラックへ）、先頭のクリップが再生位置（右クリックではその位置）に来るように置く。複製は群の末尾（span）の直後。すべて 1 つの Command（`compose`）で 1 回の Undo。右クリックの複製・削除も、複数選択中はグループに効く。
- **見送った案**: 貼り付け先を選択トラックからの相対位置にする（Logic 流）。元トラックに戻す方が「4 トラック丸ごと」の用途に素直で、説明も要らない。リストエディターからのクリップ操作。
- **互換性影響**: なし（クリップボードはメモリ内のみ）。
- **検証**: 単体 `editing.test.ts`（copyClips / pasteClips / duplicateClips / moveClips / deleteClips）、E2E `context-menu.spec.ts`（Shift+クリック、Shift+ドラッグ、⌘D、貼り付け、Delete、全トラック選択→切り取り→貼り付け）。
- **追記（同日）**: 範囲選択を Shift なしの普通のドラッグにした（DAW の流儀。「ドラッグで複数リージョンを選んで複製したい」という声に合わせて）。空いているところのドラッグでクリップを作るのは描画ツール（P）のときだけ。最後のトラックの下から始めるドラッグも範囲選択になる。Shift / ⌘ / Ctrl を押していると選択に追加。

## ADR-059 — クリップの範囲内に後から加えたイベントはそのクリップに所属する（2026-11-03）

- **背景**: クリップの `eventIds` は作成時（描画ツールでのドラッグ、SMF 読み込み）に固まり、その後に録音・入力したノートはどのクリップにも入らなかった。クリップの右クリック「クオンタイズ」はクリップが持つノートだけを対象にするので、録音した 28 個のうち作成時にあった 4 個しか揃わず、「クオンタイズしても揃わない」ように見えた。クリップの移動・削除・複製も同様に後から入れたノートを置き去りにしていた。
- **決定**: `addEvents` で `clipId` の指定が無いとき、各イベントの onset がそのトラックのクリップ範囲 `[startTick, endTick)` に入っていればそのクリップに所属させる（重なるクリップがあればプロジェクト順で最初のもの）。録音（`applyTake`）、ピアノロール・ドラム・リスト・ステップ入力、CC / Pitch Bend 入力、クリップ無しの貼り付けがすべてこの経路を通る。範囲外のイベントは従来どおりどのクリップにも属さず、クリップの範囲は広げない（ADR-005 の onset 所属の規則に合わせる）。`clipId` を明示した呼び出し（クリップの貼り付け、音色設定）の挙動は変えない。
- **見送った案**: クリップのメニューで「範囲内のノート」を対象にする（クオンタイズだけ直り、移動・削除は置き去りのまま）。録音時に範囲を覆うクリップを自動で作る・広げる（既存クリップの端を動かすのは利用者の意図と衝突しうるので今回は入れない）。
- **互換性影響**: プロジェクトファイルの形式は変わらない。既存のプロジェクトで既に外れているノートは自動では戻さず、クリップの右クリック「範囲内の外れたノートを取り込む（n 個）」（`adoptFreeEvents`、外れたノートが無いときは無効）で取り込む。
- **検証**: unit `editing.test.ts`（範囲内の 2 件が所属し、範囲外の 2 件は所属しない、範囲は変わらない、Undo で戻る。`adoptFreeEvents` は範囲内の外れたイベントだけを取り込み、無ければ null）。既存の録音・貼り付け・GS 設定のテストはそのまま通る。E2E の録音・編集・コンテキストメニューの spec を 3 ブラウザで実行。

## ADR-060 — クリップの無いところに入力・録音したノートにはクリップを自動で作る（2026-11-03）

- **背景**: ADR-059 で既存クリップの範囲内に加えたイベントは所属するようになったが、空のトラックへの録音やクリップの外への入力はどのクリップにも入らず、トラックビューでは見えるのに選べず、移動・複製・クオンタイズができなかった。DAW では録音した範囲にリージョンができるのが普通で、その感覚と食い違っていた。また、クリップに属さないノートはクリップ内のノートと見分けがつかなかった。
- **決定**: `addEvents`（`clipId` 指定なし）で、どのクリップにも入らなかったイベントにノートが 1 つでもあれば、新しいクリップを作ってそこに所属させる。範囲は最初のイベントの小節頭から最後のイベント（ノートは終端）の小節末までを拍子マップで求め、そのトラックの隣接クリップの端で切り詰める（重ならない）。既存クリップの隙間が複数にまたがるときは隙間ごとに 1 つ作る。CC / Program / SysEx だけの追加（ミキサー値・音色・ベンド幅の設定、トラック追加時の Program Change）ではクリップを作らない。トラックビューでは、クリップに属さないノートをアクセント色の枠線だけで描き、属しているノート（塗り）と区別する。ピアノロールでクリップ内のノートを範囲の外へ動かしたときにクリップが伸びる挙動（`refreshClipBounds`）は、ノートが外れて迷子になるよりよいと判断して変えない。
- **見送った案**: 隣接クリップを伸ばして取り込む（録音のたびに既存クリップの端が動くのは意図と衝突しやすい）。入力 1 回ごとに 1 小節のクリップ（連続入力で小さなクリップが並ぶ）。
- **互換性影響**: プロジェクトファイルの形式は変わらない。単体テストで「イベントを追加してからクリップを作る」手順は、追加時にクリップができるようになったので「クリップを作ってから追加する」に直した。
- **検証**: unit `editing.test.ts`（CC だけではクリップができない、ノートは小節に揃ったクリップに入る、既存クリップの中に始まり外へ続く録音は中が所属し残りが次のクリップになる、隙間では隣のクリップで切り詰める、Undo で戻る）。typecheck / lint / build。E2E 全 spec 3 ブラウザ 197 件。


## ADR-061 — 静的ビルドを PWA として配信する（2026-11-03）

- **背景**: インストールとオフライン起動の要望。既存の静的ホスティングとローカル保存を維持する。
- **決定**: manifest、既存ロゴから生成した PNG アイコン、本番のみの Service Worker 登録を追加。静的ページ生成後にビルド内の全ファイルを列挙し、内容ハッシュをキャッシュ版にする。同梱 SF2・AudioWorklet・遅延ロードするコードも事前保存する。scope ごとのキャッシュを使い、更新の activation 時にその scope の旧版のみ削除する。skipWaiting は使わず、編集と再生の途中では新版へ切り替えない。
- **見送った案**: 音源の初回利用時だけ保存（初回再生がオフラインでは動かない）。PWA 用の追加ライブラリ（今回の静的ファイル保存では不要）。即時更新と強制リロード（編集中のデータや再生への影響）。
- **互換性影響**: プロジェクト形式は不変。初回保存と新版取得では数十 MB のダウンロードが発生する。SF2 不在のビルドでもインストール可能だが、再生にはユーザーの音源が必要。開発サーバーは登録対象外。
- **検証**: typecheck / lint / build 成功、単体・結合テスト 233 件成功。`tests/e2e/pwa.spec.ts` は Chromium でルート／`/MIDIStudio/` 配信とも成功（オフライン起動・実音源再生・ヘルプ表示）。OS 側のインストール操作と聴感は未確認。
